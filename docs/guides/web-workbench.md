# 本地网页工作台

安装/更新 TNB 后，在项目目录运行：

```sh
tnb web
```

源码构建也可以直接使用：

```sh
bun run build
./dist/tnb web --cwd /absolute/path/to/project
```

命令按需启动原来的持久后台服务，打印工作台链接。将链接粘贴到浏览器，60 秒内打开一次即可；网页随后用短期 cookie 继续工作。链接过期、退出或服务重启后，重新运行 `tnb web` 获取新入口。

升级前已经启动的旧后台进程需要先执行一次 `tnb runtime restart`。跨版本升级仍受原有插件代际校验约束；持久状态会保留，但缺少任务固定的旧代际时会阻塞，不能把重启当成自动任务迁移。正常打开网页不重启后台、不打断活跃任务，也不修改模型配置。关闭网页和终端不会取消任务；停止整个后台仍使用 `tnb runtime stop`。

```sh
tnb web --cwd /path/to/project --port 8765
tnb web --config-dir /path/to/tnb-home --json
```

默认绑定 `127.0.0.1` 的随机端口；已启动的网页监听器可服务多个工作目录。每个目录有独立 URL 前缀和 cookie 范围，页面只能查看和操作本次 CLI 授权的目录。它不是公网或远程多用户管理后台。当前完整后台服务支持 macOS/Linux；Windows 定向验证不表示 owner 已移植。

## 可以做什么

- 提交 Coding 长任务，选择模型、自动/单 Agent/允许多 Agent 模式、总费用上限和轮次。
- 明确授予写入/Shell 权限；写入需要验收命令，Shell 和检查沿用原生沙箱。选择 skill/MCP 时仍使用[持久能力合同](durable-capabilities.md)。
- 查看执行阶段、模型请求与已记录费用、子任务、已验收报告、检查输出、改动预览和事件记录。
- 向指定任务追加要求，暂停、恢复、取消；暂停排空后调整费用/截止时间，更新后保持暂停。
- 自动接收待回答问题、路由目标选择和完成/阻塞通知；回答沿用原问题版本，不增加权限、不自动恢复暂停的任务。
- 对未知副作用提供已核实的外部结果。这个操作只登记证据，不重发工具调用。

当前列表沿用现有视图，展示最多 32 个活跃/最近任务；更早历史可通过原 CLI 查询，持久记录不会因此删除。

网页与终端使用同一 Run、日志和命令处理。网页提交后，在终端 `tnb runtime list/status/result` 中可以看到同一任务。插件只有 `tnb.tasks/v1` 的工作目录视图，不拿到 Runtime 对象、SQLite、控制 key 或模型凭据。新增业务领域仍由 domain adapter 定义工具与验收；当前网页创建表单面向 Coding。

## 提醒、草稿与重试

页面保持实时连接，已有未答问题会在第一次连接和每次重连时重新发送。新问题自动出现在关注栏；没有正在编辑的表单时弹出问答框，编辑草稿时保留输入并通过关注栏、页面标题和提示通知提醒。可以点击“开启桌面提醒”，授权后在页面后台时显示系统提醒；具体展示受浏览器和系统设置影响。

任务草稿、模型选择、未发送的追加要求和回答草稿按目录保存在当前浏览器。清理浏览器数据会移除这些本地草稿，但不会删除后台任务或已记录的回答。

网络超时后不要再创建一个同目标任务。工作台保存原命令并提供“重试原提交/重试原请求”，恢复使用同一 commandId；用户明确放弃重试前，不会自动换一个 ID 重发。某些版本冲突需要先查看最新状态再放弃旧请求并重新操作，不能用重试覆盖别人的决定。

## 插件管理与生命周期

网页由 `tnb-web` 的 `interface:web@1` 实现，沿用统一安装、信任、固定代际、服务授权和清理协议：

```sh
tnb plugins disable tnb-web
tnb runtime restart
```

禁用后不会回退到另一个内置网页实现，也不删除任务。重新启用同样需要重启。构建产物 `dist/plugins/tnb-web` 是可安装的独立包；手动安装后需要原有 trust/enable 流程，SDK 宿主提供并授予 `tnb.tasks/v1`。

后台停止会撤销浏览器会话、断开实时流并关闭 HTTP 端口。每会话最多 4 条实时流，整体限制 32 个目录、64 个授权链接及 64 个会话，过期和断开会清理资源。8 小时后会话到期，需要重新获取入口。授权链接不会包含后台控制 key；模型输出按纯文本显示，不执行其中的 HTML/脚本。
