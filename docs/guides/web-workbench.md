# 本地网页工作台

安装/更新 TNB 后，在项目目录运行：

```sh
tnb web
```

源码构建也可以直接使用：

```sh
bun run build
./dist/tnb web --cwd /absolute/path/to/project
```

命令按需启动原来的持久后台服务，打印工作台链接。将链接粘贴到浏览器，60 秒内打开一次即可；网页随后用短期 cookie 继续工作。链接过期、退出或服务重启后，重新运行 `tnb web` 获取新入口。

升级前已经启动的旧后台进程需要先执行一次 `tnb runtime restart`。跨版本升级仍受原有插件代际校验约束；持久状态会保留，但缺少任务固定的旧代际时会阻塞，不能把重启当成自动任务迁移。正常打开网页不重启后台、不打断活跃任务，也不修改模型配置。关闭网页和终端不会取消任务；停止整个后台仍使用 `tnb runtime stop`。

```sh
tnb web --cwd /path/to/project --port 8765
tnb web --config-dir /path/to/tnb-home --json
```

默认绑定 `127.0.0.1` 的随机端口；已启动的网页监听器可服务多个工作目录。每个目录有独立 URL 前缀和 cookie 范围，页面只能查看和操作本次 CLI 授权的目录。它不是公网或远程多用户管理后台。当前完整后台服务支持 macOS/Linux；Windows 定向验证不表示 owner 已移植。

## 可以做什么

- 默认首页是 Coding 对话：连续提问、讨论方案、读取代码、修改文件和调用工具，回复流式显示。
- 新建/切换当前目录的对话，选择新对话的模型；刷新后恢复消息和工具状态，待批准操作可以继续处理。
- 需要审批的工具操作显示名称和参数，明确选择“仅允许这一次”或“拒绝”；不会自动切换到免审批模式。
- 停止当前一轮，或将对话内容带入“转为后台任务”表单，确认任务权限与验收后提交。
- 提交 Coding 长任务，选择模型、自动/单 Agent/允许多 Agent 模式、总费用上限和轮次。
- 明确授予写入/Shell 权限；写入需要验收命令，Shell 和检查沿用原生沙箱。选择 skill/MCP 时仍使用[持久能力合同](durable-capabilities.md)。
- 查看执行阶段、模型请求与已记录费用、子任务、已验收报告、检查输出、改动预览和事件记录。
- 向指定任务追加要求，暂停、恢复、取消；暂停排空后调整费用/截止时间，更新后保持暂停。
- 自动接收待回答问题、路由目标选择和完成/阻塞通知；回答沿用原问题版本，不增加权限、不自动恢复暂停的任务。
- 对未知副作用提供已核实的外部结果。这个操作只登记证据，不重发工具调用。

当前列表沿用现有视图，展示最多 32 个活跃/最近任务；更早历史可通过原 CLI 查询，持久记录不会因此删除。

网页与终端使用同一 Run、日志和命令处理。网页提交后，在终端 `tnb runtime list/status/result` 中可以看到同一任务。插件通过 `tnb.tasks/v1` 和 `tnb.chat/v1` 的工作目录视图接入，不拿到 Runtime 对象、SQLite、控制 key 或模型凭据。新增业务领域仍由 domain adapter 定义工具与验收；当前网页创建表单面向 Coding。

## 普通对话和后台任务

普通对话复用终端执行器、模型配置、工具、Skill/MCP、权限规则、上下文整理及 SessionStore。每个对话使用独立会话身份，每轮恢复原会话；上下文来自原执行器保存的历史，不把网页上的文字列表重新拼成新提示词。新对话可以选择模型，已有对话固定原选择，需更换时新建对话。

关闭网页只断开显示，当前一轮仍由宿主管理，重新打开可查看结果或处理审批。停止按钮会取消本轮并等待执行子进程退出。宿主重启时，未完成轮次标记为中断，不自动重发；原会话存在时可以显式发送后续消息。缺失原会话文件时会拒绝空上下文续接，须恢复文件或新建对话。工具已发出的效果仍需核对，停止不等于回滚。

普通对话按终端 Coding 的当前权限规则执行；后台任务则使用原持久 Run、额度、原生沙箱和验收协议。两者各有状态，不把聊天轮次伪装成持久任务。进入“转为后台任务”表单时会带入当前输入或最近对话内容，仍须确认目标、写入/Shell 权限和验收命令后提交。

宿主最多同时执行 4 个对话，每个对话同时一轮；单轮最多 64 个 Agent 轮次、10 分钟，不能通过网页指定任意配置目录、环境、系统提示或免审批模式。页面展示最近 64 条消息，单条显示及工具输出有限额，截断会标记；执行器上下文独立保存，不随显示截断而删除。

网页投影保存在 runtime 数据库，原始 Coding 会话保存在同一 `TNB_HOME` 的 projects 会话目录。runtime 备份不包含该目录，迁移普通对话时需要另行保存原会话文件；仅恢复网页投影不能恢复原模型上下文。

## 提醒、草稿与重试

当前对话通过实时流显示工具审批，其他对话的待批准状态每 5 秒更新到关注栏并提醒。页面保持任务实时连接，已有未答问题会在第一次连接和每次重连时重新发送。新问题自动出现在关注栏；没有正在编辑的表单时弹出问答框，编辑草稿时保留输入并通过关注栏、页面标题和提示通知提醒。可以点击“开启桌面提醒”，授权后在页面后台时显示系统提醒；具体展示受浏览器和系统设置影响。

对话输入草稿、当前对话、任务草稿、模型选择、未发送的追加要求和回答草稿按目录保存在当前浏览器。清理浏览器数据会移除这些本地草稿，但不会删除宿主保存的对话、后台任务或已记录的回答。

网络超时后不要再创建一个同目标任务。工作台保存原命令并提供“重试原提交/重试原请求”，恢复使用同一 commandId；用户明确放弃重试前，不会自动换一个 ID 重发。某些版本冲突需要先查看最新状态再放弃旧请求并重新操作，不能用重试覆盖别人的决定。

## 插件管理与生命周期

网页由 `tnb-web` 的 `interface:web@1` 实现，沿用统一安装、信任、固定代际、服务授权和清理协议：

```sh
tnb plugins disable tnb-web
tnb runtime restart
```

禁用后不会回退到另一个内置网页实现，也不删除任务。重新启用同样需要重启。构建产物 `dist/plugins/tnb-web` 是可安装的独立包；手动安装后需要原有 trust/enable 流程，SDK 宿主提供并授予 `tnb.tasks/v1` 和 `tnb.chat/v1`。

后台停止会撤销浏览器会话、断开实时流并关闭 HTTP 端口。每会话最多 4 条实时流，整体限制 32 个目录、64 个授权链接及 64 个会话，过期和断开会清理资源。8 小时后会话到期，需要重新获取入口。授权链接不会包含后台控制 key；模型输出按纯文本显示，不执行其中的 HTML/脚本。
