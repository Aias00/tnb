# 渠道升级、来源绑定和故障隔离

已安装渠道和默认 `tnb-channels` 支持历史代码留存。旧 Source 按原包指纹恢复 receive/poll/send/find/observe，新 Source 默认使用当前渠道。不会用新代码冒充旧实现，也不会因恢复渠道而启动历史应用或界面。

## 绑定与恢复

来源的渠道 descriptor 与传输身份保存在宿主私有记录中。协作应用通过 `service.channel(sourceId)` 获取固定 descriptor，再连接渠道；它不再自己决定将旧 Source 指向哪个版本。内置来源保留原 Source identity，插件来源的 identity 仍包含固定渠道身份，避免改变旧事件、工单和通知的去重键。

绑定保持仓库、webhook 地址、凭据变量名、timer 参数或自定义 options 等传输配置。actor/controller 和任务权限仍读取宿主当前配置：恢复旧代码不恢复已经撤销的业务授权。已有绑定若与配置不匹配会明确拒绝，需要新 Source ID 或后续显式迁移。

启动前，宿主只做一次旧协作状态迁移：读取旧 `channel:<sourceId>` 与对应 Source identity，封存原 descriptor 和传输身份。没有完整注册事实的旧行不会获得绑定；迁移结束后，应用修改或伪造历史行不影响私有绑定。迁移不调用模型或渠道，也不重建缺失的旧代码。

默认 channels 包和 Coding 一样随编译 CLI 嵌入完整字节，使用包内容指纹。宿主另记录 channel ABI 批准，固定渠道协议、Bun、平台和架构；它与已有领域批准分开，不使原领域记录失效。独立安装包仍使用既有 trust store，启用、信任和内容校验同时满足才加载。禁用、撤权、同名安装选择、阻止指纹、缺包和归档损坏均不会触发默认回退。

## 新旧状态与生命周期

渠道注册表同时保存当前默认和精确历史实现；不带 plugin 的 descriptor 只选择当前实现，带 plugin 的 descriptor 必须精确匹配。历史渠道仅加载已被宿主引用的入口/贡献。声明贡献依赖的历史渠道会拒绝恢复，避免偷偷使用当前应用、渠道或适配器满足旧依赖；此类包需显式设计迁移或自行打包依赖。

宿主记录每个渠道状态空间的原 owner，原代际继续使用原 namespace 和目录，新代际使用含指纹的独立空间。新旧实现不能互相覆盖私有计数、游标或发送回执；无法确定旧状态 owner 时明确阻塞。应用级 Source 游标和 Outbox 保留原记录，渠道包更新不重置这些事实。

关闭会取消每代连接、等待在途调用完成，然后清理回调和临时包。历史应用不重启；当前应用仍按现有接口版本恢复自己的状态。

## 故障隔离和通知

一个 Source 缺少旧渠道或连接失败时，协作状态显示该 Source `available: false` 和错误，整体 `ready: false`。其入站返回可重试的 HTTP 503，不接纳也不确认事件。其余健康 Source 与执行内核仍可工作，不会替不可用来源改绑。不可用来源的待处理事件、游标、工单和通知保留；它们的积压不占用健康来源的接单/通知选择窗口。恢复所需包或配置后重启即可重新尝试原绑定。

```sh
tnb runtime plugins
tnb collaboration status
tnb collaboration outbox
```

已确认发送仍保持 sent；确认丢失的通知保持 unknown，即使代码恢复也不会自动重发。使用原 reconcile 或 outbox-resolve 流程核对，不把包升级视作“发送未发生”的证据。

## 保留与范围

Source 绑定存在就持有渠道代码引用。Source 暂时禁用、从配置移除，或相关 Run 已终态，都不会自动删除历史渠道包。当前没有自动退休 Source 并清理其历史绑定的命令；不要通过删除归档来强行切换来源。缺包只会让来源不可用，原业务事实保留。

旧版本默认渠道使用全宿主指纹，且没有保存独立渠道包。这样的 Source 不能仅靠升级就恢复代码；应先用原版本完成工作，或明确配置新来源。升级后的宿主会报告原来源不可用，仍允许通过本机 runtime 命令处理已有任务。独立安装的旧协作应用需要更新并重新信任，才能使用宿主提供的来源绑定接口。

SDK `openAgentRuntime` 自动读取宿主持久渠道引用。直接使用 `loadHostPlugins` 的宿主应提供完整 `channelReferences` 与领域引用；可以用 `resolveChannelBinding` 管理自己的 owner/key，但这些 API 仅供可信宿主使用。默认协作旧数据迁移只识别原 `tnb-collaboration` 的状态协议，不猜测其他应用的私有格式。

macOS/Linux 验证完整签名接单、任务执行、自动提问、升级、回答和结果通知；Windows 验证归档、注册、状态隔离、权限及迁移边界，不扩大现有后台 owner 支持承诺。插件仍是可信进程内代码，不提供进程隔离、热替换、任意历史应用/界面恢复或跨 ABI 自动迁移。

runtime backup v2 已包含代码归档和插件私有文件，备份前检查渠道绑定引用的包是否齐全；v1 仍明确缺少该覆盖。安装包、trust store、配置、外部凭据与服务仍需满足原合同，见[备份指南](plugin-backup.md)。
