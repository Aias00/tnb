# 已安装领域插件历史代际审阅

基线 `53d646a`。本轮由实现者进行源码审阅、故障场景测试及编译版验证，没有委派其他 Agent。

## 结果

- 当前默认适配器与固定指纹代际使用不同索引；同 adapter id/version 的已批准历史实现可以并存，但不能成为新根任务默认，也不能显式提交只为恢复加载的旧代际。子任务保留父任务身份，仍受原只读/资源合同约束。
- SDK 和默认常驻宿主都在 owner lock 内读取根配置与全部 task-configuration。非终态引用触发历史适配器加载，终态引用只保留包并在 inventory 显示 inactive，不执行旧 factory。
- 已安装领域包通过初始化与完整性校验后，先写入可校验的历史包，再发布注册。POSIX 刷新文件和目录后原子 rename；Windows 刷新文件后 rename。崩溃残留暂存目录不成为有效代际。
- archive 的身份、manifest、包树指纹、原安装目录、当前包信任与原指纹批准都需匹配。内容改变、缺失、禁用、移除、撤权以及撤权后仅信任新版本均不能复活历史代码。历史根目录、代际目录、包目录和元数据拒绝符号链接。
- 历史包只初始化含 adapter 的入口；混合入口仍校验其完整注册声明，但旧 application/interface/channel 不进入扩展宿主，不重启旧应用。当前包初始化失败时，新任务明确失败，不能退回旧实现。
- 新提交将请求摘要、规范化命令、配置、Run 和原回执原子提交。精确重复请求可在不初始化终态旧代码的情况下重放；旧版没有新记录的任务使用原命令回执核对，命令输入有变化仍拒绝。
- 回收依据完整宿主引用，只在启动时删除无引用且非当前的历史包；终态 Run 需显式 prune 才解除引用。没有完整引用清单的直接 SDK loader 不自动回收。

## 审阅中处理

1. 默认实现与恢复实现分离，避免当前包失败时把旧包提升为隐式默认；只为恢复加载的 adapter 不满足新根任务准入。
2. 信任历史与当前 trusted/changed 判断分开。批准新包保留旧批准，撤权则清除全部历史，防止重新 trust 新包自动恢复旧授权。
3. 子配置也持有代际引用，不能只保留 active 根配置或在任务终态时立即删除代码。
4. 重新生成旧接口的领域描述符必须发生在目录规范化之后。全量测试发现过早固定资源路径会使 macOS /var 与 /private/var 路径不匹配；修正后相关 57 项回归及最终两平台全量均通过。
5. 只有命令 ID 查找提示不构成回执证明；后续必须匹配完整旧摘要。新请求另在同一创建事务中保存精确请求摘要，解决终态代码不加载时的重复提交。
6. 运行时仍从独立临时副本执行，避免插件自己的可变资产操作改写永久历史包；关闭不删除被任务引用的历史证据。
7. 新增 Windows 安装/恢复覆盖发现原安装器按 `/` 分割路径，把 Windows 盘符路径误拼进暂存目录。改用平台 basename；本地安装/代际相关 34 项及类型检查通过，最终跨平台结果以主分支 CI 为准。
8. Windows 历史文件刷新使用读写句柄，POSIX 保留只读 fsync；Windows 的 [FlushFileBuffers 合同](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers) 要求 GENERIC_WRITE。为测试断言补充插件 inventory 错误，避免仅报告 adapter unavailable 而隐藏加载失败原因。

## 边界

这不是完整的通用多代际扩展宿主：内置 factory、历史应用/交互/渠道没有增加可执行恢复，仍遵循原指纹约束；不把已有内置任务改成安装包任务。不热替换、不做 ABI 自动迁移、不提供进程隔离。状态、凭据、资源和运行时工具合同变化仍可阻止恢复，不能只凭代码包存在就保证继续执行。

runtime backup 仍不包含可执行包、原安装目录与信任文件。灾备需另行保存这些材料，迁移路径需重新审核。历史代际会占用磁盘并计入原 runtime 存储统计；仍引用的包不会为节省空间被自动删除。
