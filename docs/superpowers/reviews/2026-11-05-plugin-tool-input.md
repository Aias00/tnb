# 外部插件工具参数校验审阅

审阅对象为[参数合同规格](../specs/2026-11-05-plugin-tool-input.md)。原外部工具只验证输入是不是对象，清单中的 inputSchema 没有约束实际派发。本轮接入共享有界 Schema 校验，覆盖工具 validate 和 runtime.call，核心 Hook/审批路径继续使用现有二次校验。

## 实现核对

参数在异步准备前检查为有界普通 JSON，并保存独立快照；合同读取后、传输启动前再次校验。前者避免静默丢失 undefined、把 NaN 变为 null 或调用自定义 toJSON；后者使直接 execute/call 也不能绕过 Schema。有效参数只作 JSON 快照，不补默认值、不转换类型、不删除字段。

Schema 复用配置校验器，并分别保留配置 128 KiB 与工具默认 1 MiB 的预算。title/description 仅作为模型注释，其他未知关键字拒绝。内联和文件合同都有限额；文件按实际读取上限处理，检查普通文件并关闭句柄，不依据 stat 后无界 readFile。

预启动先检查整包外部工具合同。校验器、原声明和模型目录相互隔离，规范化命令路径时携带已固定的合同；编辑源文件或模型可见目录不会削弱已有校验器。失败诊断包含稳定代码，不拼接参数值或解析器中的原文件片段。

## 验收证据

新增 13 项集成测试，包含 HTTP/oneshot/stdio 和真实共享 executeTool 路径。Hook 和审批改写非法输入时，派发 journal 与 HTTP 请求均为零；直接调用非法输入时，子进程启动标记不存在。有效请求仍会执行，且 200 KiB 的单字段输入不会被误用配置预算拒绝。

外部工具、权限、配置和插件发现专项通过 58 项、335 次断言。macOS 设置 `TNB_REQUIRE_NATIVE_SANDBOX=1` 的最终完整回归通过 1164 项、跳过 2 项、0 失败，共 167 个文件、4813 次断言。类型检查、构建、58 个本地文档链接及 `git diff --check` 通过。Windows 工作流加入同一份新测试，三平台远端结果以对应提交的 CI 为准。

测试日志位于本机 `/Volumes/data/tnb-review-2026-11-05/tool-input-*.log`。本轮由实现者审阅，未委派其他 Agent；测试不调用模型或外部业务服务。

## 限制和兼容

这是参数格式合同，没有引入结果 Schema、任意 JSON Schema、远端 $ref、隐式默认值或业务授权。旧 Schema 若依赖不受支持的关键字会明确失败，作者需调整为支持的方言。没有声明 Schema 时仍可接受开放对象，但不接受非 JSON 或超限结构。宿主仍须执行当前权限、工具预算及未知效果核对；校验失败不构成旧操作未发生的证明。
