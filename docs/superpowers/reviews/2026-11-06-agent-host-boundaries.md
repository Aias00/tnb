# Agent 宿主整改实现自审

对应[整改方案](../plans/2026-11-06-agent-host-boundaries.md)。本轮保留 Bun/SQLite、单 Owner 和现有终端/Web 渲染技术，交付作者合同、接入夹具、共享活动模型与受监督的进程贡献。

## 实现与审阅结论

| 项目 | 交付与兼容处理 |
| --- | --- |
| 通用配置 | `ExecutionConfiguration` / `AgentTaskInput` 独立于 Coding；`defineAgent` 按白名单构造作者上下文并执行 Schema 校验。旧 RuntimeConfiguration/持久化字段、摘要与恢复路径保留。 |
| 作者 SDK | 主入口与 testing 子路径分开打包，均生成独立声明并检查内部依赖泄漏；保留旧 API 并明确推荐合同与版本规则。 |
| 可验证业务 | 独立工单包只引用公开 SDK；配置/服务/权限显式注入，真实启动临时 Owner；验证幂等接收、重启、冲突和领域工具验收。模型与服务均为离线夹具。 |
| 交互合同 | 终端与 Web 后端使用同一个活动归约器；重试、并行工具、工具参数准备、结束响应、审批优先级与取消语义明确。两端保持各自渲染方式和既有执行入口。 |
| 进程贡献 | Manifest 明确选择，宿主不 import 用户入口；受监督的 JSON-RPC 会话支持 application/interface/channel，默认环境最小化，带帧/调用/时间/会话容量限制。 |

审阅中处理了以下问题：

1. Adapter parser 原本可能忽略执行字段；现在遇到不支持的进程 Adapter 声明直接拒绝，不能默默进程内执行。一个进程入口不得混合其他贡献；内联宿主工厂也不能冒充进程入口。
2. JSON.stringify 可能丢失函数、undefined 或对象类型；两侧在编码前校验纯 JSON、复杂度和大小，HTTP 使用有界 UTF-8 投影，不假装支持流或二进制。
3. 插件同步阻塞时无法观察 Owner 管道关闭；增加独立监督进程。POSIX 真实强杀 Owner 测试确认阻塞进程被回收；Windows 仍为 taskkill 树回收，不能宣称 Job Object 强保证。
4. 进程失败不会自动重启或重发；超时之前已提交状态仍能在显式 Owner 重启后查询。CAS 写入列表纳入幂等输入，内容变化拒绝。
5. 取消前尚未派发的请求与派发后的请求不能混淆；测试分别按真实时序断言，共享进程中已派发取消会使其他请求一并失败。
6. 编译 CLI 不再依靠某一种虚拟文件路径推断执行模式；复用构建身份，并在各平台 CI 对编译产物执行应用/渠道冒烟测试。
7. 流量/回调预算按 60 秒窗口计量，避免正常长驻渠道因生命周期累计额度耗尽而停止。
8. 初始渠道游标在 JSON 中用 null 传输，在业务调用边界恢复为 undefined；已保存的 null 分类结果也视为已有业务结果，不能因此再次调用服务。

## 验证

本机 macOS 类型检查、完整构建、独立 SDK 模板/工单接入、编译版 CLI 进程测试和全套回归均纳入交付检查。Windows CI 加入进程插件、作者合同和活动模型测试；macOS/Linux 运行全套。最终数量与远端结果记录在下方交付记录。

首次本机交付验证（265f5e5）：`TNB_REQUIRE_NATIVE_SANDBOX=1 bun test` 为 **1336 pass、3 skip、0 fail，5901 assertions，199 files**；`bun run typecheck`、`bun run build` 和编译 CLI 的应用/渠道进程冒烟全部通过。54 处本地文档链接检查及 `git diff --check` 通过。GitHub 三平台结果以最终交付提交关联的 `Verify runtime` 检查为准；Windows 是定向覆盖，Agent 任务完整持久化执行及强杀进程组验证由 macOS/Linux 承担。

首轮 Windows CI 暴露异步异常 matcher 与同线程 RPC 重入的时序问题：改为先 await 捕获失败，再作同步断言，避免误触超时或在状态提交前结束测试。同时补齐 Windows CI 的 ripgrep 依赖，并将原有 Web 内容搜索的 Windows 分隔符统一为 `/`。这些修复没有跳过失败用例；本机相关进程/搜索/Web 测试 **25 pass、0 fail**，类型检查通过。

后续 Windows 的全部定向测试和构建通过，新增的编译产物验证又捕获了成功退出但空输出的情况。CLI 入口判断补充私有构建身份，冒烟先检查 `--version --json` 再检查真实插件报告，并在失败时保留退出码/stdout/stderr，避免空输出被误判为成功。本机类型检查、重建和编译插件验证通过；Windows 以最终 CI 结果为准。

## 明确边界

- 内部持久化仍保留旧 Coding 兼容字段，并未借此发布破坏性的任务格式迁移；新作者不需要这些字段。
- 进程贡献支持应用/界面/渠道；任意 Adapter 函数、同步迁移回调、服务句柄和流不自动跨进程。需要它们时走明确宿主适配。
- 监督提供故障回收，不是文件/网络沙箱或 CPU/磁盘配额。强杀可留下临时 HOME；Windows 逃逸后代约束不等同于 Job Object。
- 跨进程不把外部副作用与 SQLite 变成一个事务。业务需要幂等键、查询/核对和必要的持久业务日志；测试夹具不证明模型语义质量或跨机器恢复。
- 没有替换数据库、模型协议栈或界面框架，没有发布 npm，没有操作真实 Source；没有新增分布式调度承诺。
