# 插件配置与状态合同实现审阅

本轮补齐应用/界面的版本化宿主配置，以及应用/界面/渠道的私有记录版本预检和迁移。旧贡献保持旧语义，已纳入版本管理的空间则拒绝旧无声明代码读取。规格见[设计](../specs/2026-11-05-plugin-data-contracts.md)，用法见[指南](../../guides/plugin-data-contracts.md)。本轮由实现者审阅，没有委派其他 Agent。

## 审阅结论

清单只增加实现明确的 configuration 和 state 字段。Schema 子集有节点、深度、字节上限，不执行远端引用、默认值、类型转换和正则；不支持字段在 import 前拒绝。配置由宿主按包/贡献提供版本化 envelope，当前后台只使用用户设置，项目设置不能覆盖。公开诊断仅保留状态、版本及摘要，不回显配置值。

版本事实由宿主命名空间持有，和私有记录、状态文件及包身份分别管理。新空间初始化到目标版本；有旧记录的无版本空间只能通过显式 from:0 迁移。完整路径在执行前检查，降级、路径缺失、损坏元数据和无声明旧代码都阻止启动。已注册声明及迁移函数做快照，不因调用方之后改对象而改变合同。

迁移回调必须与清单步骤精确匹配，只取得有界的私有记录事务。记录、schema 版本和 command receipt 同事务提交，步骤失败一起回滚；已经成功的前序步骤保留，下次从检查点继续。通过真实子进程 SIGKILL 验证了 SQLite 未提交记录及版本都回滚，并验证重试后不重复执行成功步骤。

审阅额外修复普通 state.command 的句柄边界：原代码允许插件保存 tx.get/tx.save 后跨命令调用。现在同步回调结束即失效，原生 async 回调执行前拒绝，伪装 Promise 返回导致当前事务回滚；后续续体无法使用原句柄写入。

渠道版本测试沿用既有代际命名空间：新渠道保有自己的目标版本，旧归档渠道恢复原版本及记录，不自动占据旧来源的通知与游标。配置失败发生于 start、迁移和服务取得前，健康贡献继续运行。

## 验收范围

| 场景 | 已验证行为 |
| --- | --- |
| Schema 未支持关键字、非法边界、超深/超大声明 | 静态拒绝，不 import 插件 |
| 配置缺失、版本不符、类型/必需/额外字段不符 | start 前失败，诊断不包含输入 secret |
| 独立安装包配置和迁移 | 走相同加载、信任、Schema 及步骤匹配流程 |
| 旧记录无迁移路径 | 保留原记录，拒绝新贡献启动 |
| 新空间与成功迁移重启 | 初始化到目标；成功步骤不重复 |
| 步骤写入后抛错或进程被强杀 | 同步回滚记录和版本；重试后恰好提交一次 |
| 前序提交、后序失败 | 保留前序检查点，恢复只执行剩余步骤 |
| 超记录数或写入数 | 整步拒绝，不暴露半迁移状态 |
| 事务回调返回 Promise、缓存迁移/普通命令句柄 | 当前事务回滚，迟到写入拒绝 |
| 降级、元数据损坏、旧无合同代码 | 阻止恢复，不偷偷读新结构或当作新空间 |
| 新旧渠道同时加载 | 两份版本和记录各自保持原归属 |
| 项目覆盖后台配置 | 忽略项目项并提示，保留用户配置 |

## 限制

本轮部分落实 PKG-02、AUTH-03、STATE-01/02 和 REC-04，只覆盖贡献配置和私有 SQLite 记录。不是任意代码初始化前的全局静态恢复检查，可信 factory/import 仍需遵守初始化无业务副作用合同。没有配置自动迁移、记录 Schema 验证、文件或网络原子迁移、大数据分批迁移、降级转换及历史应用/界面归档。受信任同步迁移代码无限循环时仍会阻塞宿主；没有将该 API 宣称为 OS 沙箱。

所有测试使用离线模型、临时文件、真实安装包和本机子进程，没有发送外部业务消息。

## 本地验证

macOS 最终版本在 `TNB_REQUIRE_NATIVE_SANDBOX=1` 下通过 1134 项测试，2 项其他平台专属测试跳过，0 失败；覆盖 165 个文件和 4669 次断言。新增数据合同测试 21 项，相关七文件专项 66 项通过。类型检查、完整构建、28 处本地文档链接及可运行迁移样例通过。Windows 专项 CI 增加两份数据合同测试文件；Linux/macOS 继续全量回归。
