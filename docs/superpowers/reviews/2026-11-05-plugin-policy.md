# TNB 插件统一准入策略实现审阅

本轮将插件规范的第一批授权路径落到运行时。原可执行宿主检查阻止指纹，公共资源目录却未传入该策略，导致同包代码被阻止后仍可能提供 Skill 或 MCP。现在两者使用公共策略，发现、消费、资源刷新和持久 Worker 分别执行相应检查。清单版本、宿主 API 版本和持久任务摘要格式保持兼容。

## 实现和审阅结果

| 边界 | 实现 | 验收 |
| --- | --- | --- |
| 包准入 | policy 统一 blocked、disabled、信任和手动激活判断；active 不覆盖已记录的拒绝 | 同包同时提供应用、工具、Skill、Agent、命令、Hook 和 MCP；阻止后不 import 可执行入口，Hook/MCP/外部工具消费者拒绝 |
| 用户入口 | CLI、交互刷新、SDK stream CLI、资源管理及 Coding 发现传递阻止列表；缓存目录重新应用设置 | 离线 CLI 使用旧目录提交任务，模型看不到被阻止工具或 Skill；管理查询给出 blocked |
| 资源刷新 | 拒绝下一代际时先停止旧资源，不受 restart 更新策略阻挡 | 禁用、撤销信任和阻止立即进入 stop；普通受信任升级仍 deferred |
| 外部工具句柄 | stop 标记退休代际，close 关闭 manager；stdio 启动后再次检查准入及进程归属 | HTTP 计数证明旧句柄不再次派发；stdio 启动中停止拒绝派发，宿主显式激活后可恢复 |
| 当前 Coding Worker | 记录实际选中资源的所属包，授权及工具调用复验当前设置和原内容批准 | 真实本机 stdio MCP 先调用一次，阻止、禁用、撤销信任后缓存 Skill/resource/MCP 及 Worker 授权拒绝；无额外 MCP 调用 |
| 历史 Coding Worker | 当前宿主注入领域守卫，独立于归档内的旧代码 | 真实安装包和 SQLite 引用留存旧代际；创建前拒绝不启动 Worker，创建后失败关闭 Worker，authorize、execute、bindExecution 后的工具都拒绝 |

守卫由产品 profile 注入，通用内核不依赖 Coding 资源目录。未归档 builtin 也经过加载器的可选守卫。inline adapter 属于宿主直接注册实现，由自建宿主负责相同约束。

原指纹批准和当前目录信任职责不同：运行中的 Worker 持有不可变资源快照，不因磁盘更新自动采用新内容；显式撤销原批准、禁用或阻止仍使其不可调用。准备或恢复新 Worker 继续使用已有能力 pin 校验，不能以策略复验替代内容一致性校验。没有改变未知外部效果的核对和重放协议，也不通过重新派发动作验证撤权。

审阅另修复两处边界：市场库存查询保留禁用包，避免显示成未安装；旧 stdio 子进程退出只移除自己的 runtime，不删除同键下已替换的新实例。

## 保证范围

这是包准入和受管理执行入口的首批实现，不是全部插件规范的一致性认证。尚未提供所有交互资源的逐调用动态撤权、任意进程内 JavaScript 的强制终止、所有 oneshot/HTTP 在途请求的统一排空、远端 MCP 历史实现留存、HTTP 重定向/DNS 目标约束或统一有界输出读取。后台包选择依赖重启；交互已加载资源依赖刷新或重启。已发出的效果不能当作已回滚。

本轮由实现者审阅，没有委派其他 Agent。测试使用离线模型、临时存储、本机 HTTP 和真实 stdio MCP，不调用付费模型或外部业务服务。

## 本地验证

macOS 最终版本在 `TNB_REQUIRE_NATIVE_SANDBOX=1` 下通过全量测试：1070 pass、2 skip、0 fail，覆盖 160 个文件、4330 次断言。两项跳过分别为仅适用 Linux 的 capability 继承验证和仅适用 Windows 的 best-effort 能力验证。类型检查、构建和 11 处本地文档链接检查通过。Linux CI 继续运行完整测试，Windows 原有原生沙箱及持久恢复测试集合新增本轮插件策略测试；CLI 原生会话用例保留 macOS/Linux 范围。
