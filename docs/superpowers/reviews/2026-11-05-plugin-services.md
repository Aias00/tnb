# 类型化插件服务实现审阅

本轮落实服务规范的第一批可执行合同。原 `service<T>(string)` 仅核对名称与 grant，再返回任意值；类型由消费者断言，缓存值也缺少通用生命周期约束。现在新增结构化 ServiceRef 和宿主选择的同步提供者，通过依赖预检、方法门面、作用域和在途调用等待约束使用。默认 Web、协作和渠道已迁移，旧清单及稳定 API 入口保持兼容。

设计与边界见[规格](../specs/2026-11-05-plugin-services.md)，使用方式见[服务指南](../../guides/plugin-services.md)。本轮由实现者审阅，没有委派其他 Agent。

## 审阅决策

1. 引用按 id、版本、scope 和公开方法结构比较，不依赖 bundle 内的模块单例、Symbol 或对象身份。ServiceRef 编译期包含完整方法类型，工厂结果再次检查函数集合；参数和业务权限仍由服务校验。
2. 工厂只由宿主选择。重复提供者和旧表冲突属于装配错误；服务依赖缺失、循环、合同及作用域倒置只阻止相关贡献。服务依赖和贡献依赖分别管理，不能靠服务声明扩大插件 grant。
3. host 工厂不取得消费者身份；contribution 工厂分别绑定应用、界面及每条渠道连接。根方法不暴露服务内部字段，保留原 this 绑定，每次调用检查当前作用域与授权。任意可信闭包的作用域捕获不被类型系统伪装成隔离保证。
4. 旧字符串消费者可以取得新工厂门面；旧 raw Map 明确保留兼容语义，不冒充新保证。类型化引用消费 raw Map 时要求宿主显式适配，不静默信任其结构与生命周期。
5. 服务在首次 lookup 创建。async 工厂预检失败；伪装 Promise 返回值不发布门面，但已开始的初始化仍纳入关闭等待。工厂失败不隐式重试，部分资源清理一次，错误保留。
6. 根方法 Promise 与 track(operation) 的嵌套工作均有 owner。关闭期间禁止新调用，等待实际完成后再逆序清理。依赖晚于提供者首次实例化时仍按图清理，不按 Map 插入顺序猜测依赖。
7. TaskService 工作目录视图和协作 bridge 的嵌套异步调用也纳入等待。协作准入停在 normalize 时取消，恢复执行后不能提交新准入记录；既有业务回执核对继续走原状态协议。
8. 渠道 connect 接受可选消费者 signal；独立连接的服务和取消互不串用。连接构造后的失败清理也属于在途操作，宿主不会仅看到 port 创建完成就提前结束关闭。

## 验收证据

| 场景 | 已验证结果 |
| --- | --- |
| 引用方法参数类型错误或不存在的方法 | 类型检查拒绝，完整方法集不可缺失 |
| 独立安装 bundle 创建另一份引用 | 同结构可用，返回宿主选定的能力 |
| 合同版本、方法、scope 不匹配或服务未授权 | 工厂前拒绝；独立健康贡献继续启动 |
| 同名工厂、raw Map 冲突、缺失/循环依赖、host 依赖 contribution | 装配或预检拒绝，不执行相关工厂 |
| 缓存根方法、消费者结束、复用 scope key 替换身份 | 无新调用；其他活跃消费者仍可用 |
| 无效工厂、部分初始化及清理异常 | 不隐式重试，执行全部已登记清理，保留失败 |
| 方法或伪装工厂忽略取消 | 关闭 Promise 保持未完成，直到实际工作结束 |
| 嵌套工作尚未派发或规范化正在等待 | 未派发工作不执行；在途规范化须排空且不得提交新准入 |
| 多条渠道连接、构造中取消、部分 port.close 仍在途 | 独立服务实例，缓存失效只影响原连接，宿主等待完整清理 |
| 工作目录视图缓存及 attention 流 | owner 取消后拒绝新调用，实时流关闭 |
| 默认插件及旧宿主示例 | 原 Web、协作、渠道和历史代际测试继续通过 |

## 尚未交付的保证

本轮部分落实 SVC-01 至 SVC-04、AUTH-01 和 LIFE-01/LIFE-03，不是全部规范验收。只提供 host/contribution 两种作用域；没有通用 Run/call DI、配置 Schema 和状态版本迁移，也没有任意返回对象的自动深层撤权。旧 raw Map、任意进程内 JavaScript、回调自己创建但未登记的资源仍受原兼容和信任边界约束。服务方法当前没有统一的调用期限与强制终止器；忽略取消时保留等待，而非释放所有权后宣称停止。

验证使用离线模型、临时存储、实际安装包和本机资源，不发送真实外部业务消息。
