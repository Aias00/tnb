# 协作插件服务权限收敛审阅

范围：默认宿主的服务表/授权、协作包 manifest 与入口、Source 准入、任务归属、状态事务、旧回执/数据迁移、停止排空及真实渠道链路。由实现者进行源码审阅与自动化验证，没有调用其他审阅 Agent。

## 结果与已处理细节

- 删除默认 `tnb.runtime.internal/v1`，应用仅声明 `tnb.collaboration/v1` 与渠道注册表。协作配置由宿主读取并返回副本，应用入口不接收 env/configDir，不直接引用 Runtime 或 Store 实现。独立安装包验证只需新的服务合同，不需要旧内部桥。
- 应用状态只允许六个历史协作命名空间；事务只提供应用记录读写/now，结束后不能保留调用，不能读宿主私有准入/归属或写 run/wait 的核心命令回执。新增状态命令使用单独身份；旧状态回执仍按原 digest 恢复。
- 单靠 TypeScript Pick 或绑定方法不能限制任务权限，因此使用宿主私有准入记录冻结原始事件、Source/actor/thread、配置与 mode；创建/控制不接收插件任意配置。篡改应用配置副本、事件权限/动作、工单归属或外部 Run 均被拒绝。
- 任务归属在 Runtime 提交成功后记录，但 SIGKILL 仍可能发生在提交返回之前。恢复先读取原 createRun 回执并补齐归属和工单，不先解析当前领域代际、不重复提交。已有控制回执先恢复；撤权后未执行的请求仍被阻止。
- 旧版数据迁移只在升级应用运行之前执行一次，原六个命名空间、记录 ID、Outbox/渠道身份与 CAS 不变。Run 归属由对应 createRun 回执证明；完成标记之后的插件可写“历史”不能进入迁移通道；历史 rejected/ignored 事件不会被密封，即使之后授予 actor 权限并把应用行改为 pending 也不能执行。
- 任务方法在生命周期取消后拒绝新操作；状态租约最后清理，排空期间仍可记录已观察到的发送结果。不能在取消时立即禁用状态写入，否则会把已得到的回执丢成 unknown。
- 未解决的多目标事件不能直接控制任务；解析后的目标只能从原候选中选择。已冻结的动作、候选集合和 prepared control revision 不可覆盖，避免破坏原命令回执身份。
- 禁用但仍保存 Source 配置的情况返回 disabled 配置副本，不尝试激活渠道或接受准入。

## 保留的边界

服务是协作应用专用合同，不是可给任意业务的全局 Runtime 替身。渠道注册表仍是一项明确授予的能力。受信任 Node/Bun 插件处于同一进程，API 收敛不等于 OS 沙箱。

旧领域/渠道代际不因这次状态迁移自动替换。需要原代际的活跃任务仍遵循原恢复约束；旧安装式协作包需更新、重新信任并使用新服务声明。终端 TUI 整体插件化、多代际代码保留和自动迁移不在本轮完成。
