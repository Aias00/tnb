# 插件快速接入与验证审阅

目标是让作者从独立目录完成创建、校验、试跑和安装，使用指南见[插件快速开始](../../guides/plugin-quickstart.md)。本轮由实现者审阅，未委派其他 Agent。

`plugins init` 生成不依赖仓库内部路径或下载步骤的 Agent、应用/界面、渠道模板。每个包包含实现、manifest、测试输入和说明，目标已存在时拒绝覆盖。Agent 模板的离线模型经过实际工具调用及领域验收；应用模板验证 commandId 重复输入；渠道模板验证游标和发送/查询回执。

`plugins validate` 复用正式发现流程的 parser 和目录描述逻辑，增加单目录读取入口，避免同名邻居包覆盖目标。它检查包内文件、语法/default 导出、重复声明和测试文件格式，输出包外贡献/服务要求；不 import，不执行资源或授信。静态检查不证明 factory 注册正确，测试专门覆盖“静态通过但注册失败”。import 依赖闭包和业务正确性仍由实际运行验证。

`plugins test --yes` 在临时目录进行真实安装、指纹核对、仅临时信任、宿主注册/激活及场景执行，再停止并清理。默认不读取用户设置来注入模型配置或服务授权，也不假造服务提供者；进程内代码仍能访问当前环境与用户文件。需要宿主依赖的业务使用 SDK 显式组装测试环境。场景要求报告/状态/回执断言，未知字段与缺场景不能被静默忽略。它是可信插件的进程内执行，不是 OS 沙箱，也不提供忽略取消代码的强终止保证。

8 项新增集成测试覆盖三种模板的重复试跑、用户配置不变、静态检查不导入代码、同名目录、语法/导出/文件错误、错误测试字段、factory 漏注册、业务期望错误、失败工具回执、已存在目录和命令参数。新增接入专项 8 项通过、0 失败；既有发现与管理专项也通过回归。新增窗口平台定向测试覆盖静态校验及应用/渠道；Windows 的 Agent 任务试跑明确拒绝，其原 POSIX artifact 屏障未在本轮绕过。

macOS `TNB_REQUIRE_NATIVE_SANDBOX=1` 全套回归：1211 通过、3 跳过、0 失败，173 个文件、5131 次断言。类型检查、构建通过。编译版 CLI 在独立工作目录中走完三个模板的 init/validate/test；开发命令结束后配置目录仍不存在。应用包随后经 install/trust/enable，默认 owner 显示 active，真实扩展请求返回预期 JSON；没有修改 default profile 或宿主路由。验证不调用付费模型或外部业务服务。

CLI 帮助和 Bash/Zsh/Fish 补全加入新命令，嵌套帮助不触发变更。最终平台结果以提交对应 CI 为准。本地日志保存于 `/Volumes/data/tnb-review-2026-11-05/plugin-onboarding-*.log`。

本轮提供四类宿主代码贡献的入门及验证路径；没有把 Skill/MCP/Hook 全部运行检查或当前 Coding CLI 的任意领域路由宣称为已完成。安装 Adapter 后仍由 SDK 或业务宿主选择；生产模型、服务授权、来源配置和领域断言由实际业务决定。后续应继续沿真实业务接入补缺口。
