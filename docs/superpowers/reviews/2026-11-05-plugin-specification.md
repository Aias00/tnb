# TNB 插件规范草案审阅

审阅对象为 [规范草案](../specs/2026-11-05-plugin-specification.md) 与 [源码比较](../../plugin-specification-research.md)。本轮由实现者审阅，没有委派其他 Agent。产物为设计文档，未改动运行时、清单解析或授权行为。

## 结论

以包交付、宿主扩展和持久恢复分别订约束，并保留集中状态所有权，适合当前 TNB。现有四类贡献足以承载本轮目标；没有为对齐其他框架而新增通用插件类型或引入 Cordis、Effect、Backstage。规范必须按阶段落到宿主和执行器，再通过一致性测试成为稳定承诺。

## 审阅中明确的边界

1. **版本不混用。** 包 SemVer、内容指纹、宿主 API/ABI、贡献/服务合同、配置和状态分别管理。本文不发布一个当前解析器不支持的新 manifest 版本或 JSON 配置例子。
2. **来源可核对。** 比较记录固定提交。OpenCode 的开发源码已具有分端入口和 Scope 注册，官网 hooks 对象示例不被当作该开发分支的完整 API。Stream Agent 作为部署 SPI/业务合同参考，不描述成动态插件市场。
3. **按需激活不削弱信任。** 静态清单可以用于目录，激活仍需授权；延迟的具体阶段必须定义。注册失败回滚只保证已管理的注册/资源清理，不能回滚任意网络效果。
4. **类型和进程的保证分开。** ServiceRef 和依赖图提升接口及作用域约束，不证明任意可信 JavaScript 闭包安全；独立进程也不自动等于受限网络和文件访问。
5. **关闭期限不伪造静止。** 超时后仍运行的进程内代码不能被假定停止，不能随即释放状态或 owner。强制终止依赖受控执行宿主和退出确认，未知写入仍需核对。
6. **权限复验不阻断审计。** 新调用、重放和读取工具缓存需要相应权限检查；授权用户查看历史审计记录不应要求重新运行已被禁用的插件。
7. **状态迁移不夸大事务。** 记录事务、文件发布和外部效果是不同提交点。跨文件迁移需暂存与恢复标记；业务网络写入不进入 Schema 迁移。
8. **恢复声明逐类验收。** 当前领域/渠道的历史代码支持不延伸为应用、界面、Skill 或远端 MCP 的完整恢复承诺。摘要只能检测变化，不能凭空提供旧字节；远端实现也不在本地包哈希内。
9. **事件先明确可靠性。** 进程内观察事件与持久业务投递分开，后者需要去重/确认。模型工具的只读、并发、幂等、重放和 reconcile 各有独立条件。

## 实施前仍需确定的具体接口

类型化服务引用和工厂的 TypeScript 定义、各贡献的配置/状态版本字段、可恢复入口的声明方式、错误代码目录及每种执行平台的能力矩阵，随对应实施轮次一起提交和验收。本轮先定义语义，不把未实现字段当成可安装合同。

调用、输出和排空预算应复用现有宿主配置并补足缺项，必须有限。具体默认值需用已有工作负载和故障夹具验证后决定，不能从别的框架照搬。多租户身份、跨节点调度、任意热更新和历史依赖闭包仍不属于当前实现范围。
