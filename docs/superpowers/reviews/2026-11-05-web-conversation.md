# Web Coding 连续对话实现审阅

原网页只接入 `tnb.tasks/v1`，因此打开后只能提交持久任务。本轮新增类型化 `tnb.chat/v1`，默认首页进入普通对话，后台任务作为独立入口保留。[规格](../specs/2026-11-05-web-conversation.md)与[使用指南](../../guides/web-workbench.md)记录实际范围。

## 实现核对

Web 仍为 interface 插件，安装版和内置版使用相同服务声明、grants 和生命周期。宿主固定真实工作目录、provider/model 和会话身份，浏览器不提交原始 runtime 配置、环境或免审批模式。HTTP 复用同源、Host、一次性入口、HttpOnly cookie 和目录范围；chat/attention 共用每会话实时流限额。

每个普通对话由原终端 SDK/CLI 执行，并在后续轮次恢复 SessionStore。展示投影不承担模型上下文；缺少原会话文件时明确拒绝续接。消息、占位和去重回执先原子保存，再启动模型；重试原命令不再次调用模型。完成时等待实际 SDK 子进程退出，并原子提交助手结果和本轮终态。

审批回调仅保存在当前在途轮次，按 chatId/turnId/requestId 核对；浏览器刷新可重新获取，已过期的决定不能批准新操作。父宿主关闭会取消并等待调用，SDK 对忽略正常终止的直接子进程进行升级终止。重启发现未完成记录时标记 interrupted，原批准不自动重建，未知效果不自动重发。

审阅中修正了三处实现细节：大文本与工具输出按实际 JSON 字节缩减后写入 128 KiB 记录，显示截断不改变原上下文；终态和消息在同一事务提交；断网不关闭 EventSource 的自动重连，也不会换新 commandId 重发。普通对话输入不受后台任务表单的提交锁覆盖。新对话默认优先选择已配置的 Provider，避免无密钥的内置选项遮住已配置模型。

## 验证

会话专项使用真实本机 OpenAI 兼容脚本模型和 CLI 子进程，覆盖多轮上下文、创建/发送去重、单次工具批准与拒绝、审批后刷新、停止、父宿主恢复、缺失原会话、大输出和授权字段拒绝。连同已有 Web/SDK 生命周期专项通过 20 项、134 次断言；不调用外部模型或业务服务。

Chromium 实测默认聊天首页、两轮对话、刷新历史、响应丢失后原命令重试、离线重连、刷新后批准工具、真实写文件、XSS 保持文本、转为后台任务、移动宽度、新对话和退出；无页面异常。桌面与手机截图、本机日志保存在 `/Volumes/data/tnb-review-2026-11-05/web-chat/`。编译版真实启动 owner/Web 后连续执行两轮，确认第二轮保留第一轮上下文。

macOS 设置 `TNB_REQUIRE_NATIVE_SANDBOX=1` 的最终完整回归通过 1171 项、跳过 2 项、0 失败，共 168 个测试文件、4856 次断言。类型检查、构建、本地文档链接及 `git diff --check` 通过。Windows 新增普通会话与 SDK 生命周期专项，三平台 CI 以最终提交对应工作流为准，不扩展为 Windows 后台 owner 支持承诺。本轮由实现者审阅，未委派其他 Agent。

## 限制

普通聊天轮次不等同于持久 Run：原始会话可继续，但未完成调用不会在重启后自动重跑。当前对话固定模型，UI 显示最近 64 条消息，执行器保留自身历史和上下文整理。原生 projects 会话目录不属于 runtime v2 备份，迁移时需单独保管。进程退出等待只覆盖受管理的 SDK 直接子进程，不宣称任意后代进程树隔离。普通对话沿用终端权限，后台任务沿用原沙箱和验收；两种运行合同分别保留。
