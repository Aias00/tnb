# 插件备份与只读检查实现审阅

原备份 v1 保存 SQLite 和执行证据，却没有 plugin-generations 或 plugin-state。历史领域/渠道已使用持久代际引用，因此仅恢复数据库不能完成插件恢复。本轮新增 v2 清单和只读 backup-check，旧 v1 保留明确的恢复兼容；原活跃任务恢复后继续暂停审阅。设计见[规格](../specs/2026-11-05-plugin-backup.md)，操作见[指南](../../guides/plugin-backup.md)。

## 实现与审阅

备份沿原离线 owner 锁和 staging 发布流程，保存历史归档、私有文件、空目录及可执行标记。发布前从快照数据库读取根/子任务配置和渠道绑定，检查全部 pinned 包的材料。缺归档、缺必要日志、不完整清单或指纹失败会删除临时备份，不发布“完整”结果。

检查器使用只读 SQLite，不经 RuntimeStore 的可写 schema 升级路径，不 import factory、运行迁移、请求模型或网络。材料验证和当前宿主静态兼容性分别报告：ABI/API 不匹配不伪装成校验和损坏，也不据此取得当前批准。

恢复校验私有 staging 中的实际发布内容。路径和祖先目录均拒绝符号链接，文件大小与总容量有限；artifact 还必须匹配内容寻址文件名。v2 插件文件不能藏在清单之外，删掉归档文件及其清单项也不能绕过数据库的 pinned 引用检查。目录/可执行位参与原指纹重建，避免“文件 checksum 相同”被误当成代码身份相同。

权限传输采用记录的可执行标记：即使备份所在文件系统丢失 POSIX 权限，也能区分材料正确与本机权限不符，恢复时按平台重建私有模式。原包来源和指纹信任仍由当前插件加载器检查，备份不会写回 trust store。Windows 不提供 Node 目录 fsync，本轮明确为文件 flush 与发布保证，不扩展为完整 owner 支持承诺。

## 验收场景

| 场景 | 已验证结果 |
| --- | --- |
| 历史包、二进制私有文件、空目录、可执行文件 | 完整保存，恢复后原包指纹匹配 |
| 当前安装升级，备份恢复旧任务 | 旧绑定解析原归档，新提交选择当前代码 |
| 原宿主信任已撤销，只复制原代码 | 历史恢复仍拒绝，不自动重新批准 |
| 缺根/渠道引用归档，或同时删材料和清单项 | 拒绝完整备份或检查，不以新代际替代 |
| 修改代码后重写文件 checksum | 仍因原包指纹不匹配拒绝 |
| 修改 artifact 后重写 checksum | 仍因内容寻址不匹配拒绝 |
| 删除空目录或丢失可执行位 | 目录缺失导致指纹拒绝；权限差异报告并可按清单重建 |
| unsafe 路径、执行标记指向 SQLite、祖先符号链接 | 发布前拒绝，目标保持空目录 |
| v1 有/无 pinned 任务 | 可恢复但明确插件覆盖缺失，不创造归档 |
| 完整归档但 ABI 不匹配 | 材料 verified，兼容性 review-required，不执行包 |
| CLI 与对话 backup-check | 不创建 owner/config 目录，备份 DB 哈希不变，无 WAL/SHM 新文件 |

## 验证记录

macOS 完整回归设置 `TNB_REQUIRE_NATIVE_SANDBOX=1`：1151 项通过、2 项跳过、0 失败，166 个测试文件，4731 次断言。新增插件备份集成测试共 17 项；包含既有维护、持久记录和代际恢复的专项共 50 项通过、0 失败。类型检查、构建及 `git diff --check` 通过。

测试日志保存在本机 `/Volumes/data/tnb-review-2026-11-05/plugin-backup/`。CI 的 Windows 专项加入插件备份、维护和持久记录测试；Linux/macOS 继续执行完整回归，远端结果以对应提交的工作流为准。

首次 Windows CI 中，新插件备份测试通过；新增覆盖的原维护测试暴露出产物写入无条件目录 fsync 和 SQLite 测试清理句柄占用。产物写入改为与备份一致的平台语义：文件先 flush，Windows 不执行目录 fsync；测试关闭数据库后回收原生语句并使用有界删除重试。保留全部维护场景，不以跳过测试代替修复。

## 仍需业务层处理

本轮部分落实 REC-04 和 OPS-01，不是完整灾备自动化。外部安装目录、trust store、配置、凭据、工作目录、原生依赖和远端服务不由 runtime 备份代办。plugin-state 按原样复制，不能保证插件未正确关闭的私有协议，也不对其内容加密或脱敏。SQLite 中原有批准事实随数据库保存，但启动仍受当前 ABI/安装/信任约束；这不是给复制包新增执行授权的接口。

路径、字节、指纹和静态合同检查不能替代包可信性、业务验收或数字签名。历史应用/界面执行恢复、跨 ABI 迁移及跨文件/网络原子事务仍不属于实现范围。本轮由实现者审阅，没有委派其他 Agent，测试使用离线模型、临时目录和本机 SQLite，不调用外部业务服务。
