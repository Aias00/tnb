# 默认 Coding 包历史恢复审阅

基线 fc4f9f2。本轮由实现者进行源码审阅、故障场景和编译产物验证，没有调用其他 Agent。

## 实现与审阅结论

- 默认 Coding 的实际执行代码改为自包含包，包内包含 manifest、代码、bundled skills 和运行时身份。编译 CLI 嵌入完整包字节，dist 可安装包使用相同内容。运行中的默认实现来自私有包副本，明确不调用 inline setup；提供自定义 workerFactory 时仍保持原 inline 合同，不伪造可恢复的闭包。
- 领域插件身份使用包树指纹，存储/引用/注册表沿用上一轮精确代际协议。宿主先校验和初始化，归档字节、记录独立批准后再发布注册。批准包含领域协议、Bun、平台和架构，不能靠修改 archive metadata 获得 builtin 权限。
- 当前/历史均受 blockedPluginFingerprints 约束；disabled 和宿主没有选择对应 package 的情况拒绝历史加载。安装包选择按大小写不敏感匹配，同名安装包即使未信任/损坏，也不能被历史内置包绕过。
- 完全相同的字节可以在被明确激活后具有多个来源，解决安装 dist 中同一 Coding 包与已有 builtin 归档冲突的问题。新增来源以原子 metadata 写入保存；旧来源、字节身份和独立 builtin 批准不会被清空。
- 历史代码只供原任务/子任务使用，不能成为新的隐式默认。终态不执行旧包，Run prune 后按原引用协议回收；未知副作用、问答、预算与原回执协议不改变。
- 默认宿主和 SDK 在 owner lock 下提供私有批准服务。插件 factory 和普通 ExtensionContext 无法获取批准表。受信插件仍是进程内代码，API 边界不构成 OS 隔离。

## 本轮发现并修正

1. Bun 输出的源文件标签受 cwd 影响，BuildConfig.root 不能完全消除差异。源码打包改为固定 cwd 的 Bun 子进程，避免改变宿主全局 cwd；跨两个启动目录生成的包指纹一致。编译版直接使用嵌入包，不在用户机器启动打包器。
2. 随包 Skill 原先把随机临时加载目录计入 pin。仅对明确带包身份的 bundled skill 使用包指纹和资源内容；用户/项目 Skill 保留原路径与内容约束。真实 bundled skill 在旧代际重启后仍通过原 pin，不重新批准新内容。
3. CLI 全局 includes(--version) 会截获 runtime answer 的问题版本参数，返回软件版本且不作回答。改为首参数匹配；根版本查询保持可用，子命令版本正确路由。
4. macOS /var 与 /private/var 路径别名可能影响工作目录与控制目录隔离判断。先 realpath 控制目录再比较，与工作目录使用同一规范路径；新增禁止进入控制目录的回归。
5. 独立安装包与默认包字节相同但来源不同，不应因归档单一来源而使当前包加载失败；允许明确激活产生的来源并存。旧代际恢复仍按当前选择校验信任，不能把 metadata 中的 builtin 标签当作批准。
6. 独立副本初始化和清理失败保留 inventory 错误，尝试剩余清理；未成功注册的包不能偷偷退回 inline factory。

## 验证

测试覆盖包内执行而非 inline fallback、宿主批准和 ABI 不匹配、指纹阻止、内容篡改、包路径越界、同名安装遮蔽（含大小写）、相同字节多来源、终态不初始化与回收、真实新旧代码分流。

真实 Coding 测试使用本地 HTTP 模型、文件 read、bundled docs-writer、版本化问题和回答，验证旧任务原 pin/代码及新任务当前代码。两个分别编译的可执行文件还验证了实际 owner 升级：原 Run、问题 ID 和已完成 read 保持不变，旧任务完成后新任务使用新实现，合计 4 次模型请求、1 次文件读取和 2 个不同任务。没有使用实际收费模型、外部 MCP 或社交渠道。

macOS 第一轮全量有一次原有 ConfigChange 文件监听用例未观察到事件，独立复验及后续全量通过；没有更改无关 watcher 逻辑。Linux 第一轮发现新增测试把 workspace 放入 control 父目录，调整测试目录后完整链路通过；没有放宽隔离规则。

本地证据目录：`/Volumes/data/tnb-review-2026-11-05/builtin-generations/`。最终计数以该目录和主分支 CI 为准。

最终本地代码：macOS 1050 pass / 2 skip / 0 fail；Linux VM 1045 pass / 7 skip / 0 fail；均为 1052 tests / 157 files，要求原生沙箱。两平台 typecheck、build 和双编译版升级探针通过。Windows 的新增可移植测试与最终跨平台结果由主分支 CI 复核。

## 未覆盖的形态

旧版本使用全宿主指纹的默认任务没有独立包，不能自动迁移。本轮也不恢复历史应用、交互或渠道，不改变它们的 provenance；领域恢复不代表整个协作 Source 已可跨升级接管。跨 Bun/平台/架构或领域协议升级明确拒绝自动恢复。进程隔离、热替换和 ABI 自动迁移尚未实现。

数据库备份不包含可执行归档，灾备需保存代码包；内置恢复还需原 SQLite 批准。原生依赖、模型/权限配置、MCP 与外部凭据仍受原执行合同约束。Windows 只验证打包/装载/归档/选择/回收，不声称完整 owner 任务恢复可用。
