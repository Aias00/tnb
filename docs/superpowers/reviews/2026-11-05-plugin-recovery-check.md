# 插件本地恢复预检审阅

审阅对象为[规格](../specs/2026-11-05-plugin-recovery-check.md)、[操作指南](../../guides/plugin-recovery-check.md)及实际实现。本轮由实现者审阅，未委派其他 Agent。

## 关键决策

预检与真实历史加载器共享 `resolveRetainedPlugin` 及贡献声明/入口检查，归档读取沿用 `readRetainedPlugin`。避免另写一套根据 inventory 错误字符串猜测的恢复逻辑。缺失、损坏、宿主不接受清单、来源、信任、阻止、内置批准/ABI 及贡献合同分别返回稳定错误码；原 inventory 的 error 文本保留以兼容已有展示，并新增 `recoveryDiagnostic`。

内置批准新增可选只读 `inspect`，原 `approved/approve` 接口保持兼容。默认批准表能区分没有记录与原 ABI 不符，自定义旧表只能提供合并原因。预检不调用 approve，不通过归档元数据自我授信。历史默认 Coding、渠道与独立安装包都走原选择约束。

当前数据库引用在扫描前复制；启用、阻止、Source 意图使用 owner 生效配置，安装和信任文件每次重新读取。终态和停用 Source 仍检查保留材料，但不要求加载已不使用的贡献。没有匹配归档时保守报告缺口，即使当前安装字节可能在正常启动时重新归档。

扫描不 import，不执行 factory、迁移、连接或业务调用。入口必须在包内且为普通文件。专项曾发现复用路径校验函数时误传相对入口，导致有效历史包被拒绝；已改为解析到包根下的绝对路径，再复用原路径校验，领域/渠道实际跨升级恢复继续通过。

相同引用快照并发共享一个扫描，不同快照明确报忙，避免取消旧扫描后又在存储关闭期间访问批准表。关闭立即拒绝新扫描、取消检查并停止扩展准入，等待检查/扩展排空后再处置包；不会为等待文件读取而继续接受新扩展业务。调用者得到独立结果副本，预检不回传任意 parser/manifest 错误正文。

## 验证与边界

测试真实安装/归档/加载，逐项比较预检与实际历史加载器的错误码。覆盖缺失/篡改字节、宿主版本不符、撤销批准、停用、指纹阻止、来源变化、内置批准缺失/ABI 变化、缺贡献/入口、目录入口及历史渠道依赖。数据库快照与导入日志验证预检无持久写入或旧代码执行；另验证已运行快照不被磁盘新包替换、并发返回副本、关闭取消与关闭后拒绝。SDK、RPC、CLI 和对话入口共用同一实现。

macOS 开启 `TNB_REQUIRE_NATIVE_SANDBOX=1` 的最终完整回归为 1203 项通过、3 项跳过、0 失败，172 个文件、5064 次断言。类型检查、构建、79 处本地文档链接及 `git diff --check` 通过；远端结果以提交对应 CI 为准。关闭顺序补充后，宿主/渠道生命周期、预检与 API 专项 31 项通过、0 失败。编译版 CLI 在临时配置中验证空清单报告与停止后不自动启动；另写入一条停用 Source 的真实持久绑定，重启后 `--check` 返回 `PLUGIN_ARCHIVE_MISSING`，仍保留引用且不连接该 Source。测试未使用付费模型或外部业务服务。

Windows 定向测试继续覆盖实际领域/内置/渠道代际，并加入预检投影单元测试；macOS/Linux 执行全套，Windows 不据此宣称完整 owner 执行支持。日志保存于 `/Volumes/data/tnb-review-2026-11-05/plugin-recovery-*.log`。

本功能限定为在线 owner 的本地包恢复检查。它不是离线数据库总预检，不证明状态迁移、完整业务授权、凭据、远端服务、转录/操作核对已经通过；这些项在 `unchecked` 中明确列出。文件可能在检查后变化，实际执行仍按原合同复验。Source 退休、历史应用/界面恢复、历史渠道依赖闭包和跨存储灾备仍未交付。
