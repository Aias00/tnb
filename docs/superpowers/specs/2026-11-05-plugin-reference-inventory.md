# 插件持久引用清单和回收准入

本轮落实插件总规范 REC-03 的引用解释与完整清单准入，并补充 OPS-01 的只读诊断。不实现 Source 退休或完整恢复预检。

## 合同

1. 领域清单和渠道清单分别由宿主提供。省略任一清单表示未知，禁止历史回收，包括暂存目录回收；明确 `[]` 才表示该类没有引用。没有历史目录也不执行回收。SDK 和默认产品组合负责两份完整清单，插件不能提交宿主清单。
2. 所有持久 Run 根配置、子任务覆盖配置、渠道绑定均保留其精确包身份。终态 Run 的 `load=false`；停用或移除的 Source 可以 `load=false`，但不得据此释放保留引用。包名、版本、指纹共同分组；任一引用要求加载就标记该代 `load=true`。
3. 新增 `GET /plugins/references`、`runtime plugins --references` 与 `/runtime plugins --references`。原 `/plugins` 数组保持兼容。报告区分清单完整性、当前引用理由、内存实现状态与启动回收结果；`list().references` 继续表示启动时计数。
4. 产品报告读取实际 owner 的 RuntimeStore，使用该 owner 已生效的协作配置快照。不能重读磁盘配置后把尚未重启生效的意图当作当前策略。SDK 每次查询同样重新读取持久事实。读取不加载/导入历史代码，不回收、不修改记录、不做网络请求。
5. 回收只在持有 owner 锁的启动阶段执行。报告中的 `collection.phase=startup` 固定说明这是启动结果；查询后的引用变化不隐式触发回收。回收失败可报告失败及错误，不能宣称原子回滚已删除内容。
6. `retain` 和 `load` 是保留及加载需求，不是磁盘材料完整、当前信任、连接健康或可恢复性承诺。没有匹配的内存实现时返回空 `implementations`，仍保留引用理由。SDK 无插件宿主时也能列出持久事实，明确没有运行回收。

## 验收

遗漏任一/全部清单时旧渠道归档与暂存目录不删；完整清单允许清理暂存目录，停用绑定继续保护旧代码。终态、子任务覆盖、实时新增、prune 后引用消失与实际归档延迟回收分别验证。混合贡献包按完整身份合并理由，不误匹配同指纹的不同版本；查询结果不可反向修改宿主对象。API、CLI、对话命令使用同一当前 owner 事实，保留旧列表接口。补充没有历史根及回收失败的诊断测试。

Source 退休仍需未决业务事实预检、保留历史回执的墓碑、恢复兼容屏障和备份引用一致性。不得以删除绑定或历史目录作为本功能的使用步骤。
