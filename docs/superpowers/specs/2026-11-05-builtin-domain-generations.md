# 默认内置 Coding 包的历史恢复

基线 fc4f9f2。前一轮只保存已安装领域包；默认 Coding 由内存 factory 注册，身份依赖全宿主源码指纹，不能序列化为历史实现。本轮把默认 Coding 转为随宿主交付、实际经插件加载器执行的独立包。旧包、旧任务和新任务分别绑定原始包字节，不把新 factory 贴上旧身份。

- build 在编译 CLI 之前生成完整 Coding 包：bundle、manifest、bundled skills 和 Bun/平台/架构边界，嵌入可执行文件；源码运行按相同打包流程生成，进程内缓存。包指纹按真实树字节计算。默认加载器从该包的私有副本执行，不能继续执行另一套 inline factory。
- 通用 builtin 合同允许显式提供 packed package。自定义 workerFactory 仍为原 inline builtin，不能归档未提供的可执行代码。旧版全宿主指纹不会自动迁移，也不自动换成独立安装包身份。
- 当前内置包成功校验/初始化、留存后，宿主在 SQLite 私有命名空间记录身份和恢复 ABI 的批准。历史加载必须同时拥有原包、原批准、当前同名 builtin 选择，以及相同 Bun/平台/架构/宿主领域协议。metadata 自称 builtin 不足以获得权限。
- 同名已安装包（包括失败/未信任/禁用）仍完全阻止 builtin 默认和历史回退，保留现有信任语义。settings 可按 fingerprint 阻止任一当前/历史领域代际，宿主重启生效；整体 disabled 也阻止历史加载。
- 保留根/子配置引用、终态不初始化、回执去重、精确解析和 prune 后回收。历史包损坏、缺少批准或运行时 ABI 不匹配时诊断明确，原任务暂停。
- 默认 profile 与 openAgentRuntime 都在 owner lock 下提供宿主批准表。独立 SDK loader 必须显式配置该服务才能保存/恢复 builtin；插件 factory API 不得到此表。

验证使用自包含 fixture 包和真实 Coding 包，覆盖新旧默认分流、等待/回答/子配置和重启、篡改来源/内容、缺批准、禁用、指纹阻止、安装包遮蔽和终态回收。编译版用两个真正不同的内置包构建升级恢复，确认旧 Run/问题/工具回执持续存在，执行旧包而不是新代码。macOS/Linux 完整验证，Windows 验证插件装载与归档边界，不扩大 owner 支持承诺。

不包含历史应用/交互/渠道恢复、热替换、进程隔离、跨 ABI 自动迁移或旧版内置任务迁移。数据库备份仍不含可执行包。恢复 ABI 固定是兼容性拒绝机制，不证明任意宿主行为变化都安全；重大领域合同变化必须提升协议。
