# 插件本地恢复预检

落实总规范 REC-01、REC-04、OPS-01 的本地包部分。不把本地包检查扩展成完整灾备或可立即恢复任务的承诺。

## 范围与语义

1. 提供 `GET /plugins/recovery`、`tnb runtime plugins --check`、`/runtime plugins --check` 和 SDK `host.plugins.checkRecovery()`。只连接当前 owner，不能自动启动服务；检查范围是其全部持久领域/子任务/渠道引用，包含终态与停用 Source。直接宿主须传完整引用清单。
2. 使用当前 owner 生效的启用/阻止策略、内置包选择和配置快照，重新读取当前安装目录、trust store 和归档字节。结果与内存实现状态分别呈现；磁盘更新不切换已加载实现。
3. 归档检查复用原 `readRetainedPlugin`：真实目录、元数据身份、包指纹、manifest/宿主合同。历史来源、信任、内置批准/ABI 与贡献声明校验由预检和实际历史加载器共享。自定义批准表缺少 `inspect` 时只能报告批准/ABI 的合并原因。
4. 只读校验精确 id/version 对应的 Adapter/Channel 声明和入口路径。历史渠道的贡献依赖仍拒绝，不启动历史应用或界面，也不因检查通过执行 factory。实际激活继续校验注册结果、快照和当时授权。
5. 返回 `scope: local-plugin-recovery`、`status: local-checks-passed|issues-found`、引用快照和每代的稳定 `code/phase/retryable`。完整清单为空时明确没有检查任何代际；省略清单不能成功。诊断只回传宿主代码与身份，不把任意 manifest/解析错误文本带入预检报告。
6. `unchecked` 必须列出尚未检查的 factory/注册、配置和状态迁移、当前资源授权、凭据/远端服务及 transcript/operation 核对。不能把 `local-checks-passed` 表述为完整恢复就绪。
7. 同一宿主只运行一个扫描，相同引用快照的并发请求共享扫描但各返回独立副本；不同快照返回 `PLUGIN_CHECK_BUSY`，调用方稍后重新查询。扫描结束不缓存文件检查结果。
8. 扫描属于宿主生命周期。关闭拒绝新查询，取消并等待扫描，再处置插件和关闭存储、释放 owner。检查可以等待读取完成，不能在数据库关闭后继续通过批准表查询。没有发业务操作，不能改变 unknown 效果或迁移记录。

## 保守证据与边界

本功能检查持久归档材料，当前安装精确匹配但归档缺失时仍报告缺口。实际启动可能从仍存在且可信的当前包重新归档；预检不会替用户启动或修复。任一阶段失败即报告该代首个前置问题，修复后再次扫描；其他代际继续检查。

报告是当前观察，不能与安装目录、信任文件或远端状态构成跨存储原子快照。它不替代实际执行前复验，也不执行迁移、审批、连接、核对或重发。离线恢复前的数据库/业务材料总预检、Source 退休和完整灾备仍需后续实现。

## 验收

真实已安装领域/渠道及打包内置代际覆盖成功、终态、子任务、缺失/损坏/不兼容归档、撤销信任、停用、阻止、来源变化、批准缺失、ABI 不兼容、缺声明/入口及历史依赖拒绝。比较预检与实际加载器错误码；检查前后数据库快照和导入日志不变。验证并发合并、不同快照拒绝、返回副本、关闭取消与关闭后拒绝。API、CLI、对话命令与编译版产物使用同一路径。
