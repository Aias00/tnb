# 渠道历史代码与协作来源恢复

基线 a125092。当前渠道按 kind/id/version 单索引，协作应用先选当前渠道再比旧绑定，故旧 Source 不能跨升级恢复。本轮使已安装渠道和默认 channels 包拥有可执行历史，并让协作来源恢复原绑定。

- ExtensionHost 将当前默认和精确渠道代际分开，裸 descriptor 只选择当前实现，显式 plugin 身份只解析该实现。恢复模式只注册被引用的历史渠道，不启动历史 application/interface；历史渠道若声明贡献依赖则拒绝，避免把旧代码与当前依赖隐式混合。服务仍按原声明及当前 grants 校验。
- 当前渠道包成功注册后留存，非终态来源引用加载旧包，未启用的来源仅保留字节。绑定记录存在就持有引用，不会因为 Run 终态或 Source 从配置移除而删除渠道字节。没有原包的旧全宿主指纹不能自动迁移。
- 默认 channels 改为随 CLI 嵌入的独立包，以内容指纹绑定，使用独立 channel ABI/宿主批准表，不改变既有领域批准 ABI。纯渠道包复用原安装器、trust store、代际快照和回收。
- 协作宿主先读取/封存来源绑定，应用通过限定 Source ID 的服务取 descriptor，不能自行替换。绑定固定 transport 配置和渠道身份，actor/controller 仍读取宿主当前配置。一次迁移只采纳启动前的旧应用绑定，并核对历史 Source identity，迁移后应用伪造历史行不能获得宿主准入。
- 恢复前 host 依据绑定收集 channel refs；升级后旧 Source 使用旧实现，新 Source 使用当前实现；显式改绑、传输配置改变、撤权/禁用/阻止指纹/缺包均拒绝。未知出站结果仍保持 unknown，恢复不得自动重发。
- 渠道状态按持久 owner 记录区分代际。原 namespace 保留给原代际，新代际使用含指纹的 namespace/目录，防止新旧实现同时改写旧游标/回执。关闭取消每代信号、等待在途调用后再清理和删除临时包。

验证使用真实文件/SQLite、本地 HTTP 和脚本模型：新旧渠道分流、精确解析、私有状态隔离、原问题/游标/Outbox 回执、来源配置不可偷换、迁移后伪造、禁用/撤权/损坏/缺批准、在途排空，以及两个不同编译版完成签名接单→read→提问通知→升级→回答→结果通知，保持原 Run/问题/通知身份。

不包含任意历史应用/交互代码恢复、渠道依赖代际闭包、热替换、进程隔离和旧内置代码重建。渠道批准固定 Bun/平台/架构/渠道协议；身份及代码恢复不绕过当前凭据与业务权限。旧 Source 没有归档时明确阻塞，不能自动指向新实现。
