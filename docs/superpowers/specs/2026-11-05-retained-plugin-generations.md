# 已安装领域插件的历史代际与恢复

当前加载器只保留宿主生命周期内的临时副本，DomainRegistry 以 adapter id/version 唯一索引。更新已安装包会导致旧任务在重启后找不到原指纹。本轮补齐已安装领域插件的可执行包留存与多代际精确解析，不热替换运行中的实现。

- owner lock 获取后打开 RuntimeStore，读取全部 Run 配置和 task-configuration 中的插件身份。非终态任务需要加载，终态任务仍引用历史包，直到显式删除 Run。没有引用清单的 SDK 加载器不自动回收。
- 当前已信任包完成初始化、校验后，将完整包字节原子保存到宿主 plugin-generations/<identity digest>/package。临时代际目录继续隔离运行时读写，关闭只删除临时副本。
- 历史包必须匹配持久身份、包内容指纹、manifest 身份及原安装目录。重新检查兼容性，不扫描和执行未引用的历史包。不启动历史 application/interface/channel，不把历史代码作为当前安装包失败时的默认回退。
- trust store 保留同一安装目录明确批准过的指纹；当前包仍只按最新批准指纹判断 trusted/changed。撤销信任清除该目录全部代际授权；重新信任当前代码不恢复旧授权。禁用、卸载和缺失安装包阻止历史加载。
- 注册表将当前默认与精确代际分开。默认提交使用当前包；历史实现只用于解析已固定描述符，子任务继续继承父任务身份。新根任务不能选择仅为恢复而加载的旧代际。
- inventory 显示 current/retained、引用数和历史加载失败原因。只有全部引用都已删除、且不是当前实现的历史包才在下次启动时回收。崩溃遗留暂存目录在 owner lock 下清理。损坏包保留诊断，不当作有效历史包导入。

验证覆盖：同包同 adapter/version 改字节后，新旧任务分别执行对应实现；等待问答跨升级恢复且工具不重复；缺包/损坏/篡改/撤权/禁用/卸载均不能绕过；未引用历史不执行；子配置引用被保留；回收不删除仍引用的终态包；全量测试、类型检查与构建。

边界：内置 factory 没有独立的历史可执行包，仍按原指纹阻塞，不以新代码冒充旧实现。历史渠道/应用/交互恢复、插件进程隔离、ABI 自动迁移不在本轮。数据库备份不自动包含可执行包，恢复部署还需保存历史目录和 trust store。
