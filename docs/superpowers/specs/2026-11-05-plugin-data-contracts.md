# 插件配置和私有状态合同

本轮在应用、界面和渠道的贡献声明中增加可选 state 合同，在应用和界面中增加可选 configuration 合同。旧声明维持旧语义；旧宿主已有严格字段检查，会明确拒绝这些必需新字段，不使用包 SemVer 代替配置/状态版本。

实现用法见[指南](../../guides/plugin-data-contracts.md)，验收与范围见[审阅](../reviews/2026-11-05-plugin-data-contracts.md)。

配置由宿主按包和贡献提供 `{version,value}`。清单固定配置版本和有界 JSON Schema 子集，启动前验证，配置错误只影响所属贡献。Schema 预检不 import 插件代码；不支持的关键字拒绝，不执行默认值、强制类型转换、远端引用或正则。配置仅在内存传入，诊断包含版本/摘要但不输出值；宿主重新启动才应用更新。

私有状态的版本记录属于宿主命名空间。新状态直接初始化到目标版本；已有无版本记录以 0 表示，只能通过显式声明和注册的迁移升级。迁移步骤精确 from/to，单向且无歧义，注册与清单必须一致。未声明 state 的旧代码不能读取已纳入版本管理的空间，降级和缺迁移路径都拒绝。

迁移只取得该贡献的同步 get/list/save 事务句柄，没有宿主服务、文件路径和网络 API。每步以 SQLite 事务提交记录和版本，异常则一起回滚。迁移成功后重启不重复执行，失败保留旧版本并可重试；命令身份和内容指纹可审计。单步扫描与写入有数量及字节上限，超过范围拒绝，批量迁移另行实现。可信 JavaScript 自行访问外部资源仍需作者遵守合同，不声称沙箱隔离。

迁移在贡献 start/connect 和服务取得前执行。渠道继续沿原代际状态隔离规则；迁移不改写渠道来源 provenance、任务绑定、回执和 unknown 效果。预检与结果在现有贡献 inventory 中单独显示。配置迁移、文件暂存发布、跨存储原子迁移和大数据批次不在本轮范围。

验收覆盖非法 Schema、版本与内容错误、诊断不泄露配置、无版本导入、跨版本迁移、崩溃事务恢复、失败回滚、降级拒绝、失效事务句柄及旧声明兼容，并保持默认 Web/协作/渠道和历史恢复回归。
