# 插件恢复材料备份合同

现有 v1 运行时备份只覆盖 SQLite、对话、操作日志和任务产物，缺少历史包和插件私有文件。本轮引入 v2 清单，新增 plugin-generations 和 plugin-state，保留目录结构与可执行位；不包含安装目录、trust store、用户配置、环境或工作目录。

已实现流程和边界见[指南](../../guides/plugin-backup.md)，验收结果见[审阅](../reviews/2026-11-05-plugin-backup.md)。

备份仍在停止服务后的 owner 锁内完成，先检查引用的历史包是否齐全且指纹一致，再把数据库和受管理文件写入临时目录，完整校验后发布。v2 必须覆盖数据库中 Run/Task/渠道绑定引用的全部包身份和文件材料，缺失时失败，不以当前新实现替代。私有状态中的符号链接和非普通文件拒绝，不跟随到外部。

新增只读 backup-check，验证路径、校验和、SQLite 一致性和历史引用材料，不执行 factory、迁移、模型、工具、远端请求，也不打开 RuntimeStore 的可写迁移路径。报告单独说明备份材料完整性及当前宿主兼容性；后者不等同于当前信任、外部账户和远端可用性。

恢复接受 v1/v2。所有证据先复制到私有 staging 再验证，发布前不得修改目标；恢复后的原活跃 Run 继续暂停并要求审阅。v1 可恢复但明确缺少插件文件覆盖；v2 不以遗失历史包的备份声称完整。复制归档不是新增信任，运行仍经当前宿主的启用、批准和 ABI 检查。

单文件最多 512 MiB、清单最多 100000 个文件、总文件材料最多 10 GiB，目录和嵌套另有限额。POSIX 文件与目录均同步；Windows 只保证所用文件 flush 与 staging 发布，不声称提供 POSIX 目录 fsync。跨账户凭据、安装来源路径迁移、外部服务以及任意状态文件业务一致性仍依赖各插件原合同。
