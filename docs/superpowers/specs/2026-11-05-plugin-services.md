# 类型化插件服务合同

本轮在现有清单和 `tnb.host-plugin/v1` 上增加类型化宿主服务；不增加清单字段，不让插件注册或替换内核服务。持久配置与状态迁移另行实施。

实现与使用方式见[服务指南](../../guides/plugin-services.md)，验收范围见[实现审阅](../reviews/2026-11-05-plugin-services.md)。

服务引用固定逻辑 id、合同版本、host/contribution 作用域及公开方法集合，生成与现有清单兼容的 `id/vN` 名称。插件、宿主和独立 bundle 按该结构匹配，不依赖对象或 Symbol 身份。引用提供编译期类型，宿主再次检查工厂结果包含全部声明方法，只发布这些方法。

服务提供者由宿主显式选择。重复提供者及旧值表与新工厂重名拒绝装配；依赖需显式声明。缺失、不匹配、循环及 host 服务依赖短生命周期 contribution 服务在工厂执行前检查，失败只阻止相关消费者。

host 工厂每个宿主创建一次，不接收消费者身份；contribution 工厂按实际消费者创建实例。两者均同步创建接口，异步资源经接口方法打开。方法保持原同步/异步语义，调用前校验贡献和服务生命周期，异步调用由宿主追踪。旧字符串查找可以取得新工厂的受管理句柄；旧 values Map 保留显式兼容模式，类型化引用不能把其原始值冒充新工厂。

停止先拒绝调用并取消 signal，再等待已开始的服务方法和 track(operation) 登记的嵌套工作，最后按依赖图逆序清理实例。缓存根句柄不越过生命周期；返回的嵌套业务句柄仍由各服务明确实现作用域和清理。默认任务、协作和渠道服务补齐这些检查；渠道连接按消费者取消并等待，不能把共享渠道注册表等同于共享连接权限。清理期间的既有回执记账沿原业务协议，不允许重新取得新服务。

验收覆盖独立 bundle 的引用兼容、类型误用、声明/授权、版本/方法/作用域不匹配、工厂结构、依赖图、缓存方法、异步排空、失败回滚、渠道连接取消及默认 Web/协作行为。可信进程内代码忽略取消时继续等待，不伪造超时后的静止或 OS 隔离。Run/call 作用域、通用配置 Schema 和持久状态版本迁移不在本轮范围。
