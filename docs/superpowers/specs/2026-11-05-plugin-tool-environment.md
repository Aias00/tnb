# 外部工具最小环境和宿主凭据引用

## 问题

原 PluginToolRuntimeManager 把宿主传入环境逐项交给 oneshot/stdio 子进程，Provider 密钥、TNB 配置身份、SSH agent、代理和加载参数可能被无关工具继承。已有网络、取消和 Schema 合同没有处理这个边界。本轮落实 AUTH-03/05 和 LIFE-01 的外部工具路径，不声明任意进程隔离。

## 合同

1. 子进程默认使用有限运行变量和每包代际/工具独立的 HOME/TMP/XDG/Windows 配置目录。源环境拍摄快照，不直接枚举传递所有变量。目录归 runtime 管理，正常排空后删除。
2. 宿主用户配置 `pluginToolEnvironment` 仅保存包名、内容指纹、工具 ID 和目标变量到宿主变量的引用。项目、显式 settings overlay 和插件本身不得增加该授权。与当前包指纹不符、引用不可用或试图覆盖保留字段时拒绝执行。
3. 仅适用 oneshot/stdio。HTTP 工具不能把该授权转为 Header 或请求参数，也不改变原目标/代理/重定向合同。模型不能通过输入改变引用或读取宿主环境。
4. 配置更新先关闭新准入，取消并等待在途调用与受管理进程，清理旧目录后启用新策略。旧工具句柄固定原环境身份，变更后拒绝复用。引用表变化是宿主安全策略，不受插件的 ConfigChange veto 控制。
5. 等价引用顺序规范化，不因无语义变化取消工作。源环境值轮换通过替换宿主环境并重建 runtime 完成。包信任和凭据授权分别校验，授权不会因为批准新包而自动迁移。
6. 私有环境创建、stdio 启动必须合并并发。异步准备后重新检查 owner/停止状态/进程限额，不能在停止后从旧准备结果创建进程。激活意图在第一次 await 前固定停止 epoch，更新的停止意图优先。
7. Schema、配置和数量/字节限额有界；不将密钥值保存到配置、目录声明、任务参数或通用诊断。受管理输出/错误做获批值的精确替换，不宣称通用 DLP。

## 验收和边界

使用真实 Bun 子进程验证默认缺失宿主密钥/加载参数、私有目录、指纹与工具隔离、授权传入、stdout/stderr 替换、并发初始化、撤权等待与旧句柄、配置来源、数量限制和停止优先。通过安装/信任的编译工具及真实 CLI/SDK、本机脚本模型验证完整配置路径。原 HTTP、Schema、权限和停止测试继续运行，Windows 执行同一组专项。

私有 HOME 是短期空间，不是插件持久状态，强制终止宿主后的遗留目录未实现自动回收。文件访问、网络和进程树受 OS 权限及各自运行合同约束；本轮不提供额外沙箱、任意进程内撤权、完整秘密存储服务、历史账号迁移或跨文件事务。完整操作和兼容变化见[环境指南](../../guides/plugin-tool-environment.md)。
