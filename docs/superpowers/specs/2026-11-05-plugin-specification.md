# TNB 插件规范草案

状态：设计草案。基线为 `5128162`；新增要求须经实现及一致性测试后才成为稳定承诺，本文不改变当前清单/API 的可执行行为。依据与取舍见 [源码比较](../../plugin-specification-research.md)。

首批实现为统一包准入策略，覆盖发现时的指纹阻止、资源刷新撤权、停止后的外部工具句柄，以及当前和历史 Coding Worker 的资源策略复验。使用方式见[宿主指南](../../guides/host-plugins.md#统一准入策略和撤权)，实现边界和验收见[准入策略审阅](../reviews/2026-11-05-plugin-policy.md)。这只落实 AUTH-01、AUTH-02、SVC-04 和 REC-01 的部分路径，不表示下列全部规则已交付。

后续已落实外部插件工具的 HTTP loopback 直连约束、拒绝重定向、调用期限、读取字节限额、并发/常驻进程数上限、取消及直接子进程退出等待，见[运行合同](../../guides/plugin-tool-runtime.md)和[实现审阅](../reviews/2026-11-05-plugin-runtime.md)。这部分落实 AUTH-05 和 LIFE-01 至 LIFE-05；任意进程内扩展、后代进程树隔离、最小环境、MCP/Channel 的统一预算及配置/状态迁移仍未交付。

类型化 ServiceRef、宿主工厂依赖预检、host/contribution 作用域和受管理句柄已落实，默认 Web/协作/渠道使用同一合同；嵌套任务调用及渠道构造清理也纳入等待，见[服务规格](2026-11-05-plugin-services.md)、[使用指南](../../guides/plugin-services.md)和[审阅](../reviews/2026-11-05-plugin-services.md)。该阶段部分覆盖 SVC-01 至 SVC-04，Run/call 作用域及任意进程内强撤销仍未交付。

贡献的版本化配置、有界 Schema、私有记录版本与事务迁移已实现，参见[数据规格](2026-11-05-plugin-data-contracts.md)、[指南](../../guides/plugin-data-contracts.md)和[审阅](../reviews/2026-11-05-plugin-data-contracts.md)。这是 STATE-01/02 和 REC-04 的部分路径；配置自动迁移、文件/网络原子迁移、大数据批次及完整备份恢复诊断仍未交付。

运行时备份 v2 现已覆盖历史包和插件私有文件，并以数据库引用检查材料齐全；只读 `runtime backup-check` 区分材料完整性与静态 ABI/宿主兼容性，见[备份规格](2026-11-05-plugin-backup.md)、[指南](../../guides/plugin-backup.md)和[审阅](../reviews/2026-11-05-plugin-backup.md)。外部安装、信任、账户、工作目录与远端业务可用性仍需原执行合同验证，不将其宣称为完整自动灾备。

本文使用“必须”表示准入要求，“应”表示通常需要满足且例外须说明的要求，“可以”表示可选能力。规范覆盖包、贡献、宿主服务、模型工具、状态及恢复，不将安装信任等同于恶意代码隔离。

## 权威状态和扩展职责

**CORE-01** 任务、子任务、问答、预算、资源准入、owner/fencing、工具回执和终态提交由宿主掌握。扩展只能经限定的宿主命令修改这些事实。普通服务或事件监听器不得提供绕过准入的原始数据库及完整 Runtime。

**CORE-02** Adapter 提供业务 Worker、输入快照、验收和可选 reconcile；Application 组织业务流程；Channel 提供外部接收、轮询、发送及查询；Interface 提供用户入口。Skill、MCP、工具、命令和 Hooks 必须登记所属包、贡献或宿主资源来源，不得因不属于四类可执行贡献而绕过包策略。

**CORE-03** 安装、启用、信任、可激活、已运行、业务可用分别表达。插件的 `active` 不能作为其所有来源、连接或任务已经可用的证明。持久状态记录配置意图、任务绑定、迁移和业务回执；连接及观察到的运行阶段在重启后重新建立，不能重放一条旧 active 记录冒充资源仍在运行。

## 包和版本

**PKG-01** 可执行包必须有可静态读取的清单、稳定包身份、兼容范围、已声明贡献和包内入口。安装、列表与兼容预检不执行 factory 或安装脚本。必需能力、可执行字段、依赖或生命周期选项不受支持时必须明确拒绝；不得接受字段后忽略语义。

**PKG-02** 以下版本独立管理，不能互相代替。

| 标识 | 管理的问题 |
| --- | --- |
| 清单版本 | 字段如何解析、旧宿主能否识别必需能力 |
| 包版本及内容指纹 | 交付的代码和资源是哪一份；SemVer 不能替代字节身份 |
| 宿主 API 版本及恢复 ABI | 插件能调用哪些稳定接口；保存代码能否在本宿主恢复 |
| 贡献/服务合同版本 | 调用方与提供者的方法和业务语义是否兼容 |
| 配置版本 | 已保存配置如何校验和显式迁移 |
| 状态版本 | 记录与私有文件如何读取、迁移及处理降级 |

当前保留 `manifestVersion: 2`、`tnb.plugin/v1` 与 `tnb.host-plugin/v1` 的真实语义。新版本号和字段需随实现确定，不将本表直接作为当前可执行清单样例。

**PKG-03** 包指纹必须包含运行所依赖的包内代码、资源和已交付依赖。信任决定绑定到实际字节。启动使用校验后的私有副本；复制和初始化后复验。包外依赖或远端服务不属于该指纹的完整性保证，必须单独描述其版本与可用性条件。

**PKG-04** 可恢复贡献应有独立入口，入口导入和注册不得发起业务写入。若多个贡献共用 factory，该 factory 必须满足全部声明的初始化规则；过滤注册结果不等于隔离了未选择贡献的初始化动作。无法保证这一点的共享入口不得声明支持选择性历史恢复。

**PKG-05** 稳定接口不得在原 API 版本下任意改变调用语义。实验接口必须明确标记、显式选择，并与稳定恢复合同分开。弃用需保留迁移说明和兼容验收；不能因包版本尚小就破坏稳定 v1 调用方。

## 注册与激活

**REG-01** 清单声明在代码执行前建立目录。factory 仅能注册本入口声明的贡献；重复、缺失、越界及初始化结束后的注册必须拒绝。包注册全部校验成功后提交，失败逆序释放已取得资源，独立包继续可诊断运行。注册回滚不能被表述为撤销了任意远端副作用。

**REG-02** 名称冲突必须说明两个提供者和冲突贡献。当前默认、显式替换和历史恢复是不同选择；已安装同名包失败、被禁用或未获信任时不得偷偷回退到内置包。新任务不得隐式选择 recovery-only 实现。

**REG-03** 按需激活必须定义延迟 import、factory、start 或 connect 中的哪一步，记录触发原因，并合并同一代际的并发激活。贡献只在依赖和服务授权满足后发布；依赖失败阻止其消费者，不把缺少必需能力的任务当作无工具任务继续。

**REG-04** 服务端、TUI 和 Web 代码必须声明运行位置及可用合同。后台不为列出界面而执行界面入口；界面不得取得宿主控制 key 或渠道凭据。分端入口的代码身份属于包，注册及释放属于各自运行位置和代际。

## 服务和扩展点

**SVC-01** 服务定义、提供者与扩展点分别注册。服务引用必须提供稳定 ID、合同版本、类型和作用域；插件扩展点是其明确开放的配置/贡献接口，不能因获得普通服务权限就任意注入其他插件内部实现。

**SVC-02** 宿主明确选择并校验服务工厂。声明、授权、版本兼容、依赖存在和作用域规则同时满足后才创建实例。普通插件不得替换内核授权、预算或状态提交服务。TypeScript 类型辅助同进程开发，持久输入、配置、模型 JSON 及进程通信仍需运行时校验。

**SVC-03** 资源至少区分宿主、插件代际、Run 和调用的归属。长生命周期实例不得捕获短生命周期的用户、凭据或取消状态；需要短作用域能力时使用按调用打开的受限句柄。共享实例必须可安全处理并发调用，不能保存全局 current user/current request。宿主检查声明的依赖关系与句柄使用；可信代码内部的任意闭包捕获仍需作者遵守合同及并发验收，类型系统不构成隔离保证。

**SVC-04** 服务句柄必须校验自身生命周期和业务作用域。缓存句柄不能在原 owner 结束后继续提交命令；停止后允许的排空记账仅能核对原操作，不能开始新操作。服务依赖形成可诊断图，缺失、循环、不兼容及非法作用域依赖明确拒绝。

## 授权与执行方式

**AUTH-01** 资源发现、目录展示、注册、激活和实际执行共用宿主策略。包来源、启用、内容信任、阻止指纹、贡献授权及资源授权必须一致应用。已暴露给模型、返回缓存结果或属于历史包，均不免除调用时应执行的当前权限检查。查看已有审计记录遵循当前读取权限，不要求重新激活被禁用的旧代码。

**AUTH-02** 调用权限是当前宿主策略、该任务已准入资源和本次调用范围的交集。模型、Skill 指令、检索内容及插件声明不能扩大它。撤权后不得开始新效果；取消不证明已经发出的效果被撤销。可信进程内代码无法被 API grant 强制隔离；强撤销要求受控的执行进程。

**AUTH-03** 配置和凭据由宿主掌握。模型只选择允许的业务参数或已准备操作，不得传入任意入口代码、账户、服务地址、文件根或授权字段。任务保存必要的配置身份与摘要，凭据正文不得进入任务记录、日志或模型上下文；账户和传输身份变化必须重新准入或显式迁移。

**AUTH-04** 规范必须区分可信进程内执行和具有 OS 约束的受限执行。进程内扩展的声明用于宿主管理，不宣称阻止恶意模块自行访问文件或网络。受限外部工具必须实际执行文件、网络、子进程和环境限制，平台不支持必需保证时拒绝启动，不能静默降为无沙箱。

**AUTH-05** HTTP loopback 限制须在真实目标和每次重定向执行时校验；任意外网目的地、DNS 解析和代理改变不能绕过目标合同。受限执行使用最小环境及显式凭据引用。没有 shell 包装只能说明启动方式，不能据此认为子进程无法自行启动 shell。

## 生命周期和资源限额

**LIFE-01** 每个订阅、计时器、服务实例、渠道连接、文件句柄、进程及在途调用必须有 owner。注册返回可释放句柄或自动纳入 owner 的清理集合；重复 close/dispose 等待同一完成结果。不得在作用域结束后留下脱离 owner 的后台业务调用。

**LIFE-02** 注册、迁移、启动、健康、请求、排空和停止分阶段记录。超时和限额由宿主策略确定，对激活、单调用、输出、并发、排队及清理分别给出有限预算。贡献可以申请更小预算，不能扩大任务剩余期限或宿主上限；部署选项必须校验且有实际使用点。

**LIFE-03** 停止先拒绝新准入、取消工作，再等待在途调用和逆序释放，最后关闭状态与 owner。清理异常不能跳过其他清理。进程内调用超时后仍未静止时不能删除其可用状态、释放 owner 并宣称完成；需要强制保证时由隔离执行宿主终止、等待进程退出，并按原操作记录不确定结果。

**LIFE-04** 插件 I/O 不得占有全局命令串行区间。串行区间仅保护权威状态的短提交，外部调用使用预留/派发/回执步骤。慢插件不得阻塞其他插件或任务的取消、问答和状态查询；相同操作的幂等与顺序由命令和资源作用域保证。

**LIFE-05** 输出读取过程必须限制总字节、单帧/单行、保留日志和结果大小，并并发排空必要的 stdout/stderr。超过限额立即按协议失败或有界截断，不能完整分配后才截断展示。输出截断必须保留事实，验收不得把缺失证据当作完整结果。

## 持久状态和迁移

**STATE-01** 状态明确归属、Schema 版本和读取兼容范围。业务事实、插件私有记录及宿主安全记录分开；插件不能自行改写信任、代码批准、Source 绑定或权威任务记录。普通持久变更使用宿主 command、revision CAS 和稳定幂等键。

**STATE-02** 状态迁移在贡献接收业务前执行，输入为明确的源/目标 Schema，保存进度、结果和稳定迁移身份。纯记录迁移及可重试批次必须可安全重入。大状态分批迁移时，在最终兼容状态提交前不得向业务暴露半迁移数据。

**STATE-03** SQLite 事务不能原子覆盖任意文件和网络。文件迁移必须采用暂存、校验、原子发布与持久恢复标记，崩溃后能判断继续或清理；迁移不得顺便发业务写入。降级只在旧代码明确能读取目标状态时允许，否则拒绝并说明恢复选择。

**STATE-04** 两个代码代际并发时，私有状态空间必须分开，除非使用单独声明的共享状态协议并验证兼容。变更状态所有者和目录身份必须有可恢复的迁移事实，不能让新代码先占据旧游标或发送回执。

## 任务绑定与模型可见能力

**RUN-01** 新任务由宿主解析领域目录和配置，固定原贡献版本、代码指纹、必要配置、资源范围、服务合同及工具目录摘要。CLI、Web 和渠道使用同一准入服务；不为每个业务在入口新增权限分支。历史任务解析原绑定，缺实现则阻止执行并报告具体原因。

**RUN-02** 插件安装或目录变化不会自动给已有任务增加工具。模型只接收该任务允许的名称、描述和参数 Schema；真实执行前再次校验工具归属、当前权限及最终参数。Hook 改写参数后必须重新校验，不能在授权完成后追加更大范围的请求。

**RUN-03** Skill 的指令和选定资源必须有可核对的版本/内容身份。MCP 工具固定宿主准入的目录和配置身份；目录变化不能扩大当前任务。摘要匹配只能发现变化，不能替代缺失历史字节的留存。需要恢复的指令和资源纳入显式保留范围；不能重建时拒绝换成新内容。

**RUN-04** 业务协议至少提供输入及结果 Schema、准备后的领域描述、资源要求、验收和副作用合同。Schema 使用有界、明确支持的方言；输入合规不等于业务授权，结果合规不等于语义正确。模型供应商接口、目录及价格选择仍由宿主或明确的领域策略控制。

## 依赖与历史恢复

**REC-01** 新启动解析贡献和服务依赖，任务固定宿主选择后的实际实现。恢复必须检查原代码、原合同、当前批准/授权与可用性；语义版本范围不能成为选择任意新实现恢复旧任务的理由。远端服务或凭据状态不由本地包哈希保证。

**REC-02** 可恢复能力必须逐类声明和验收。Adapter、Channel、Application、Interface、Skill 和 MCP 的恢复条件不能互相代替。当前仅允许已实现的领域/渠道历史恢复；历史应用和历史渠道贡献依赖闭包在支持前继续拒绝，不因本规范描述目标而自动开放。

**REC-03** 历史字节由持久引用保护，加载引用与保留引用分别计算。终态证据、停用 Source 及待核对操作可以继续持有代码。退休须显式列出影响的任务、问答、游标和通知，禁止有未决使用者时强行删绑定；回收不得按内存调用数或当前配置列表猜测引用已消失。

**REC-04** 恢复预检分别报告代码缺失、损坏、批准/信任缺失、ABI/状态不兼容、授权变化和远端暂不可用。备份声明包含哪些数据库、资源、私有文件、归档和批准事实；恢复不能通过复制归档或信任元数据自行提升新宿主权限。不存在的旧代码不能被自动重建承诺掩盖。

## 事件与外部效果

**EFFECT-01** 只读观察事件在权威事实提交后产生，携带稳定事实 ID 和序号；它们不承担授权和状态提交。需业务投递保证的消费者通过持久队列、去重和确认接入，不把进程内广播当作可靠投递。

**EFFECT-02** 策略 Hook 只增加拒绝或提出修改建议，不能覆盖内核拒绝。日志/展示 Hook 的失败归属消费者，不能把已成功提交的业务改成失败。涉及模型请求的包装器不得自行增加订阅、请求或重试来绕过预算；其行为也属于固定的执行合同。

**EFFECT-03** 写入超时、取消或响应丢失不能当作未执行。副作用按原 operation ID/输入摘要核对；只有明确的重放合同允许再派发。`readOnly`、并发安全、幂等、可重放和可核对分别定义，MCP annotations 或清单自述不自动授予这些保证。恢复不能自动将 unknown 改为 pending。

## 诊断和一致性验收

**OPS-01** 诊断区分包意图、信任、各贡献运行状态、连接健康、业务来源可用性与恢复能力。错误包含稳定代码、阶段、归属贡献/代际、可重试性和操作结果确定性；不得只返回一个字符串 `failed`。日志关联 Run/Task/operation，默认不记录凭据及无关原始内容。

**OPS-02** 每项稳定规范必须有测试或静态检查，默认包和安装包遵守相同合同。测试采用离线模型、临时存储和本机服务；平台不支持的能力明确报告，不用跳过测试声称提供该能力。文档、类型声明、清单 Schema 和实际错误语义同步更新。

| 验收场景 | 必须观察到的结果 | 规则 |
| --- | --- | --- |
| 清单含不支持的必需能力、API 或兼容范围 | 导入代码前拒绝，包版本不代替 API/状态版本 | PKG-01、PKG-02 |
| 被阻止包同时贡献代码、Skill、MCP、Hook 和命令 | 所有入口一致拒绝，已有暴露不能开始新调用 | AUTH-01、AUTH-02 |
| 校验到复制/初始化之间包内容变化 | 拒绝注册，不执行损坏历史或切换其他实现 | PKG-03、REC-01 |
| 恢复贡献与其他贡献共用入口 | 按已声明初始化合同验收，不把结果过滤当作隔离 | PKG-04、REC-02 |
| 初始化最后一个入口失败 | 注册未发布，资源逆序清理，其他包仍可诊断 | REG-01 |
| 同名冲突或安装包故障 | 指明提供者，不回退内置包或提升 recovery-only 为默认 | REG-02 |
| 注册/激活 API 被延迟回调使用 | 已失效句柄拒绝操作，不产生新贡献 | LIFE-01、SVC-04 |
| 当前贡献声明缺失/循环依赖，并发触发激活 | 指明依赖链，失败消费者不启动，同代激活合并 | REG-03 |
| 服务重复、不兼容或具有非法作用域依赖 | 在装配时拒绝，调用方不能自行断言类型或权限 | SVC-01、SVC-02、SVC-03 |
| 多个 Run 并发复用服务、旧句柄在停止后使用 | 身份不串用，新命令拒绝，原调用按合同排空 | SVC-03、SVC-04 |
| 后台只列出或运行服务端贡献 | 不导入界面入口，不向界面泄露控制 key/凭据 | REG-04、AUTH-03 |
| 平台无法提供插件声明的必需文件/网络限制 | 拒绝受限执行，不静默退化 | AUTH-04 |
| loopback URL、外网 URL、重定向和解析目标变化 | 按真实目标校验，越界不发请求 | AUTH-05 |
| 外部工具持续输出或发送超长无换行帧 | 在读取上限处停止，内存不随输出持续增长 | LIFE-05 |
| 插件调用停滞，同时取消其他任务 | 控制请求不被该插件 I/O 串行阻塞 | LIFE-04 |
| 忽略取消或清理失败 | 不谎报静止；保留 owner/状态，或等待受控进程终止 | LIFE-02、LIFE-03 |
| 状态迁移各提交点崩溃后重启 | 同一迁移身份继续，不重复业务写入，不暴露半迁移 | STATE-02、STATE-03 |
| 新旧渠道并存、相同命令 ID，或尝试写宿主私有记录 | 私有状态独立，原游标/回执正确，宿主事实不能越权修改 | STATE-01、STATE-04 |
| 新包安装/工具目录扩大或绕过入口直接调用 | 已准入任务不增加权限，内核保留最终状态及预算控制 | CORE-01、CORE-02、RUN-01、RUN-02 |
| 已获授权后 Hook 修改调用参数或增加模型请求 | 最终参数重新校验，请求仍经原预算与调度 | RUN-02、EFFECT-02 |
| Skill 字节缺失、MCP 目录变化、输入/结果 Schema 不符 | 不以新内容替换，不扩大权限，不将格式通过当语义正确 | RUN-03、RUN-04 |
| 写入响应丢失后升级/重启 | 原操作保持不确定，核对而不重发 | EFFECT-03 |
| 持久事件提交后消费者断开、重复拉取和确认 | 按稳定事实身份去重，不靠内存监听冒充可靠投递 | EFFECT-01 |
| Source 禁用/移除、显式退休、回收和备份恢复 | 解释保留引用和未决事实，报告缺失项，不自动授信 | REC-03、REC-04 |
| 清单启用但激活失败、渠道部分不可用 | 分层诊断，重启不重放旧 active 状态 | CORE-03、OPS-01 |
| 安装新的非 Coding 领域或使用旧版稳定 API | 标准准入可用，无业务专属入口分支，兼容失败明确 | RUN-01、PKG-05 |
| 默认包与独立安装样例执行同一合同 | 清单、类型、文档和实际行为一致，不依赖私有捷径 | OPS-02 |

## 分阶段适配现有实现

第一轮不新增清单版本，统一现有阻止、授权、网络及资源限制，补齐取消和请求隔离的执行语义。旧字段若只能表达声明信息，管理界面必须明确实际保证，不能扩大安全承诺。

第二轮再提供类型化服务、领域目录和配置/状态协议。旧插件通过明确的兼容适配层使用现有 v1 语义；对新必需能力旧宿主应拒绝，不能忽略。旧任务缺少原始元数据时只采用有持久事实支持的迁移，不能从当前配置反推授权。

第三轮完善分端交互 SDK、引用解释、Source 退休与完整恢复预检。每轮先让内置包作为普通协议消费者通过验收，再使用独立安装样例检查公开接口，避免默认包依赖宿主私有能力而外部作者无法实现。
