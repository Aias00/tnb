# Web Coding 对话接入

## 目标

原网页只提供长任务表单、Run 展示和问答，不能作为日常 Coding 入口。首页调整为普通连续对话，同时保留后台任务工作台。业务执行复用终端实现，Web 继续作为 interface 插件，不能直接取得 Runtime、SQLite 或模型密钥。

## 服务与状态

新增类型化 `tnb.chat/v1` 宿主作用域服务。贡献声明与宿主 grants 同时满足才可接入；open 固定真实工作目录，返回列表、详情、命令和快照流。默认网页同时消费 chat 和 tasks 服务，安装版使用相同声明。HTTP 沿用一次性入口、HttpOnly cookie、Origin/Host 校验和工作区路径范围。

聊天元数据、展示消息和命令回执由宿主 SQLite 保存；每轮执行复用 SDK stream-json 子进程和原 SessionStore，固定宿主选出的 provider/model、工作目录和会话身份。网页不能指定配置、环境、入口、系统提示、任意会话身份或权限模式。后续消息按原会话恢复，不以网页历史重建上下文。

消息接纳先提交用户消息、助手占位、turnId 和命令回执，再启动该轮。相同 commandId/输入重试返回原回执，不重复启动；每个对话仅一轮，宿主最多 4 轮并发。完成时等待实际子进程退出，将展示结果和终态一起提交。显示内容有界，不把 UI 截断当作执行器上下文压缩。

审批请求绑定 chatId、turnId 和 requestId，只允许当前在途请求的一次 allow/deny。原终端 deny/ask 规则仍生效；刷新重连能看见当前审批，宿主重启不会重建旧批准回调。重启发现运行中记录时标记 interrupted，不能重派旧输入或自动重放工具效果。原会话文件缺失时拒绝空上下文续接。

## 生命周期与交互

模型调用属于宿主，不绑定单个 SSE 请求；浏览器断线只关闭显示流。停止/宿主关闭会取消审批与模型请求，等待 SDK 子进程实际退出；忽略正常终止的直接子进程会升级终止。SDK 增加可等待退出接口，不用逻辑队列结束替代进程退出。

页面默认显示对话、模型选择、历史列表、工具进度和审批卡片。Enter 发送、Shift+Enter 换行；支持新对话、重试原命令、刷新恢复、停止当前轮。输出只作文本展示。后台任务仍可单独创建，也可从对话带入表单，确认权限与验收后提交。普通对话与 Run 使用各自执行合同，不扩展后台任务的恢复保证到聊天轮次。

## 验收与边界

验证真实本机脚本模型的多轮上下文、同命令重试、工具审批/写入、刷新重连、停止、宿主重启、跨目录拒绝、伪造授权字段拒绝和 cookie/Origin 约束；浏览器验证默认首页、连续对话、审批、XSS、任务入口和移动宽度。模型与服务均为本机夹具，不使用付费模型。

本轮不提供远程多租户、任意角色授权、跨节点会话、历史任意 UI 代码恢复或自动重放未知操作。runtime 备份保存网页投影，原生 projects 会话文件仍需独立备份。现有对话固定模型选择，页面显示最近 64 条消息；不以有限 UI 投影冒充无限会话历史。
