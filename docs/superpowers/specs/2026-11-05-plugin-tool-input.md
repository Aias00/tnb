# 外部插件工具参数合同

## 问题和范围

外部工具原有 inputSchema 只用于模型目录；validate 仅检查对象形状，直接 execute 或 runtime.call 也不能验证必填项、属性类型和范围。现有核心执行器已会重新校验 Hook 与审批修改的参数，但外部工具缺少实际的 Schema 校验器。

本轮落实 RUN-02 和 RUN-04 的参数路径，沿用现有清单字段和 JSON-RPC 传输。不增加包必需版本，不改变工具业务授权，不新增结果 Schema 或 MCP annotations 的保证。

## 合同

1. Schema 根必须为 object。复用贡献配置的有界 Schema 方言，工具额外支持 title、description 两种仅供模型阅读的字符串注释；不支持的断言和默认值明确拒绝，不做隐式类型转换或字段删除。
2. 内联 Schema 在发现时检查；文件 Schema 在激活/目录构造时读取。文件位于包内、为普通文件，读取最多 64 KiB；无远端引用或动态网络加载。
3. 同一运行时代际、贡献对象的合同读取结果固定。预启动先检查该包全部外部工具的合同，再创建 eager 子进程。命令规范化产生新对象时携带原快照，不重复读取 Schema 文件。模型可见目录是独立副本，修改它不能改变校验器。
4. validate 校验原始 JSON 并返回独立快照；核心执行器在模型输入、Hook 改写和审批修改处继续使用同一 validate。最终 runtime.call 再做合同校验，直接 execute/call 不免除校验。无效参数不发 HTTP、不创建子进程、不写 stdio 请求。
5. 调用接纳前、任何 await 之前保存原始输入快照，拒绝 undefined、非有限数、函数、非普通对象、循环及超限结构，不能靠 JSON.stringify 静默丢字段、转换 NaN 或执行 toJSON。
6. 工具保留原默认 1 MiB 输入预算和宿主可收紧限额，不套用配置的 128 KiB 预算。数据最多 8192 个 JSON 节点、深度 16；Schema 最多 256 个节点、单对象 64 个属性，Schema 节点及 JSON 结构均有深度限制。
7. 新边界返回 PLUGIN_TOOL_SCHEMA_INVALID 或 PLUGIN_TOOL_INPUT_INVALID，不回显参数值或原始 Schema 文件内容。验证失败不自动重试，不能改变之前已经发生的操作结果。

## 兼容和边界

未声明 inputSchema 的工具保留开放对象语义，但仍要求有界普通 JSON。此前包含不支持断言、无 type、根非 object 或依赖默认值的 Schema 现在明确拒绝；作者需使用受支持方言，不能继续接受后忽略。修改 Schema 需按原插件刷新/代际规则重新发现，不为旧目录动态替换合同。

本轮检查参数格式，不证明路径授权、远端业务许可或结果语义正确。它不增加进程/文件/网络沙箱，也不实现最小子进程环境、结果验证、任意进程内扩展隔离或 MCP 的完整 Schema 校验。CLI 的旧宽泛 Schema 不能据此宣称完整 JSON Schema 标准支持。

## 验收

使用本机 HTTP 和 Bun 子进程验证：有效/无效参数、必填/类型/枚举/嵌套/边界、直接执行、Hook/审批修改、零派发日志、模型目录被修改、文件被修改、缺失/越界/超大文件、eager 预检、JSON 丢值和 1 MiB 预算。保留原外部工具取消、资源限制、权限和配置 Schema 回归；Windows 加入同一组离线测试。
