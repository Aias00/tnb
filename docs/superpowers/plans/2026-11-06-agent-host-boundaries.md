# Agent 宿主边界与插件接入整改

目标：保留 TypeScript/Bun/SQLite 单 Owner 主栈，把通用执行、插件作者体验、交互合同与故障隔离落到实际接入。基线 ce71e47；兼容已持久化任务和已有进程内插件，不发布 npm，不更换数据库或界面框架。

## 分步交付及验收

1. **通用合同**：提供独立的执行限制/领域提交/领域上下文类型；公共领域上下文不要求文件目录、Shell、检查命令等 Coding 字段。内部持久化兼容旧记录，Coding 通过专门适配层取得旧配置。恢复、子任务、参数校验必须保持一致。
2. **SDK 与真实接入**：定义作者 API 稳定性和版本规则；提供临时测试宿主，显式注入服务与配置；增加只依赖公开 SDK 的非 Coding 业务插件，验证 Schema、服务、幂等写入、关闭重开和错误处理。
3. **交互合同**：终端与 Web 共享类型化的执行活动归约及文案语义，覆盖模型请求、响应、重试、工具、审批和取消。保留各自渲染技术；不把一次普通对话误报为可自动恢复的长任务。
4. **进程插件**：新增显式声明的进程贡献与版本化 JSON-RPC 边界。首批支持业务 application/interface/channel；Adapter 的模型/工具执行继续由现有宿主控制，不伪造任意函数的跨进程兼容。进程内合同不变。子进程只接收显式配置和受控宿主调用；有帧/并发/时间限制、取消和强制回收，进程丢失不自动重放业务请求。独立进程是故障隔离，非 OS 安全沙箱。无法跨边界表达的服务或迁移应明确拒绝。
5. **审阅与验证**：检查 SDK 包无内部模块依赖；独立项目可创建、编译、验证、测试；进程崩溃/阻塞不拖住宿主，取消不重试副作用；既有 Coding、长任务和 Web 回归通过。类型检查、构建、本机全套及精确提交 CI 通过后直接推送 main。

## 验证原则

- 使用本地离线模型、临时状态及测试服务，不操作用户真实 Source，不调用付费模型。
- 保持单 Owner + SQLite 事务，明确外部副作用未知时不能自动重试；不承诺跨机器调度。
- 先验证作者能接入，再完善必要的管理能力；不扩大到市场、Source 退休或分布式重构。
- 每阶段记录实现、证据、兼容性和剩余限制，实际实现与文档不一致时先修正实现或缩小声明。
