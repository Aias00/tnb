# 非 Coding 插件的产品接入入口

基线 5cf8828。目标是让已经安装并信任的领域插件，在默认 TNB Owner 中可发现、可显式提交、可按命名空间管理；复用持久任务引擎，不再要求用户自建 SDK 宿主。

## 范围与验收

1. `runtime adapters` 与认证的 `/adapters` 返回当前注册代际的 ID、版本、代码身份和可用配置 Schema；保留代际不能被当作新任务候选。旧 Coding/宿主适配入口明确标识。
2. `runtime submit "目标" --adapter ./task.json --namespace support` 及 `/runtime` 等价入口，读取有界纯 JSON 领域描述。与 Coding 专属权限/目录选项互斥；本地输入错误不得拉起 Owner。Owner 复用领域校验、能力收窄、幂等回执、代码固定与验收。
3. `/agent-tasks` 为认证的 JSON 提交入口；增加能力协商，旧 Owner 明确要求升级/重启。`list/followup/routing --namespace` 复用现有状态与路由协议；按 Run ID 的结果、问题、暂停/恢复/取消保持原入口。
4. 作者模板输出可直接提交的描述文件，TypeScript 构建复制到产物；文档给出创建、验证、安装、信任、发现、提交、重启和结果读取的完整闭环。
5. 离线模型及临时配置验证：默认产品服务实际安装新 Adapter 后完成任务；检验鉴权、非法能力、未知字段、无效配置、停用/保留代际、跨命名空间追加、重试与重启。类型检查、构建、本机及三平台 CI 通过后直接提交 main。

不自动替任务选择业务插件，不授予新服务或外部凭据，不让模型输出扩大能力。命名空间是业务范围，不伪装成文件目录；默认 Web Coding 工作台的业务切换不在本轮范围，通用客户端可使用认证任务/通知 API。Adapter 的生产模型与业务正确性仍由插件和宿主明确提供。
